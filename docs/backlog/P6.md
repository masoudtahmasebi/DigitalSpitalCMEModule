### P6-01 · WordPress plugin: block, shortcode and asset loading

- **jira:** _(unassigned)_
- **Estimate:** 2 h · **Week:** 2 · **Depends on:** P5-01
- **Review gate:** none

**Context**
A thin plugin whose only job is to place the custom element on a page and load its
bundle. Keeping it thin is what keeps the review conversation with the MEDICE team
small.

**Scope**

- `wordpress/ds-lms/` — a standalone plugin providing a Gutenberg block and a
  `[ds_lms]` shortcode, both rendering `<ds-lms>` with configuration attributes.
- Enqueue the widget bundle only on pages that use it, never site-wide.
- Configuration (API base URL, project identifier) via WordPress settings, not
  hardcoded.

**Acceptance criteria**

- [ ] The block and the shortcode render the same element with the same
      configuration
- [ ] The bundle is enqueued only on pages containing the block or shortcode
- [ ] No API token or secret is present in the rendered HTML or in any enqueued
      asset
- [ ] The plugin activates cleanly with no PHP notices or warnings
- [ ] Deactivating the plugin leaves the site fully functional

### P6-02 · Token endpoint in keycloakWordPressPlugin

- **jira:** _(unassigned)_
- **Estimate:** 2 h · **Week:** 2 · **Depends on:** P6-01, P1-01
- **Review gate:** human — auth
- **Implements:** ADR-0003
- **Blocked by:** WordPress repository access (roadmap §12 item 5)

**Context**
This modifies a plugin running on MEDICE's **production** site, on the login path
their business depends on. The change is therefore additive only, nonce-protected
and behind a feature flag, and is reviewed with the MEDICE team (roadmap §11).

**Scope**

- One REST endpoint returning the current user's Keycloak access token.
- Served only to a logged-in session, with a nonce check; rejects everything else.
- Behind a feature flag that can be switched off instantly without redeploying.
- No change to any existing function in the plugin.

**Acceptance criteria**

- [ ] A logged-out request receives no token, under any parameter combination
- [ ] A request without a valid nonce is rejected
- [ ] The endpoint returns only the calling user's token — no user parameter is
      accepted
- [ ] The token appears in no PHP log, no WordPress debug log and no cache
- [ ] The response carries no-store cache headers
- [ ] Disabling the feature flag disables the endpoint immediately
- [ ] The diff against the existing plugin is purely additive, verified line by
      line in review with the MEDICE team

### P6-03 · Logged-out and error states

- **jira:** _(unassigned)_
- **Estimate:** 1 h · **Week:** 2 · **Depends on:** P6-02
- **Review gate:** none

**Context**
The widget will be placed on pages that anonymous visitors reach. It must degrade
into something coherent rather than an empty box or a stack trace.

**Scope**

- Logged-out state with a prompt to log into the ADHS site.
- API-unavailable and token-refresh-failed states.

**Acceptance criteria**

- [ ] An anonymous visitor sees a clear prompt, never an empty element or an error
- [ ] An API outage renders a recoverable message, not a broken layout
- [ ] No internal error detail, hostname or stack trace reaches the page
- [ ] All states are styled within the shadow root and match the MEDICE theme
