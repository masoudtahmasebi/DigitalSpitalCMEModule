# P78 — a section that finishes, and a way out of it

Reported with a screenshot of `/medice/kurs/adhs-akademie-adult`:

> _"the video was probably 5 and a half second, and the video scroll bar is not
> done, and although the video is done, i can not go forward"_

Two defects, and the proposed fix — _"take the length of the video minus 2
seconds for completion"_ — treats a symptom of the first. Both are fixed at the
cause instead, and the watch gate is not relaxed.

---

## What the screenshot actually showed

`0:05 / 0:06`, a scrub bar stopping just short of the end — and, at the same
time, **„100 % angesehen"** with Modul 1 ticked in the outline.

Those readings are consistent with exactly one state: a stored length of **6 s**
over a file of about **5.5 s**. The bar is `5.5 / 6`, which is 92 % and cannot
reach the end however long the video plays. The section completed anyway only
because `watchedSecondsWithin`'s half-second endpoint tolerance happened to
cover the 0.5 s difference.

Which means the reported course was half a second away from being genuinely
unfinishable, and the completion that did happen was luck rather than design.

## P78-01 · the authored length may never exceed the file

`probeDurationSec` did `Math.round(seconds)`. A 5.5-second file became `6` —
and `durationSec` is the number the watch gate is a percentage of, so the gate
demanded seconds the file did not contain. This is P76-03's defect reintroduced
by the measurement that was supposed to prevent it (P75-01), just small enough
to hide under the tolerance.

`durationFromMetadata` **floors**, which makes `authored <= file` an invariant
of every measured length. Watching to the end is then always enough. It gives
away at most one second of required watching — nothing on a 25-minute lecture,
and in the only safe direction: a gate a fraction short is invisible, a gate a
fraction long is a physician who cannot finish their Fortbildung.

It is a separate exported function because the probe needs a real media pipeline
and the decision needs none. jsdom cannot drive a `<video>`, so the rule that
matters would otherwise have had no test at all.

### Why not "duration minus two seconds"

Three reasons, and the first is arithmetic:

1. **On this very video, two seconds is a third of the content.** An absolute
   tolerance is negligible on a 25-minute lecture and destroys the gate on a
   short one. Whatever the right relaxation is, it is not a constant.
2. **It is not needed.** Once the stored length cannot exceed the file, watching
   to the end always satisfies the gate. The tolerance would be covering for a
   bug that no longer exists.
3. **It is a compliance change, not a UI change.** The watch percentage decides
   a CME point. Widening the credited-completion window from half a second to
   two is a decision about what "watched" means to the Ärztekammer, and
   CLAUDE.md §7 is explicit that those are not guessed at. The existing 0.5 s is
   documented as a _sampling artefact_ tolerance — a `<video>` cannot report its
   own endpoints exactly — which is a different claim from "two seconds may be
   skipped".

If a real tolerance is wanted it should be per course and stated in the
accreditation, not a constant chosen to work around a rounding bug.

## P78-02 · „Weiter: <Abschnitt>"

The second half of the report, and unrelated to the first: the player offered
„Fortbildung pausieren" and „Zurück zur Übersicht" and nothing else. Finishing a
section left the learner with no way onward except returning to the outline and
finding the next item by hand. That is what _"i can not go forward"_ described,
and it was true whether or not the bar filled.

`nextAvailableContent` walks the catalogue for order and the **enrolment for
permission**, exactly as `findQuizContent` does. The button appears only for a
content the server has as `available`, so it can never be a control that
refuses (§9.2) — on the last section, or while the next module is still locked,
nothing is drawn and the outline's padlock remains the explanation.

Two deliberate choices:

- **It names the destination.** „Weiter" alone does not say whether it means the
  next chapter, the next module or the exam, and the sidebar shows all three.
- **It never slides into the Lernerfolgskontrolle.** The exam has its own
  button; arriving in it by pressing "next" would start an assessment the
  learner did not choose to begin.

### Acceptance criteria

- [x] A measured length is never greater than the file it was measured from
- [x] Sub-second and non-finite readings are refused rather than stored as `0`
- [x] A finished section offers the next one, when the server has opened it
- [x] Nothing is offered when the server has not
- [x] The next control skips the quiz
- [x] Red-checked: restoring `Math.round` fails three tests; ignoring the
      server's gate fails the locked-module test

## What this does not fix

**The courses already stored.** `durationSec` values written by the rounding
measurement are still one part-second long. On the reported course that is
within the tolerance and completes; on another it may not be. Opening the
content in the console re-measures and now says so (P76-03), and saving repairs
it — but nothing sweeps them, which remains P76's open item.

**The journey cannot catch this class.** Its fixture is exactly 18.0 s, so
`round` and `floor` agree on it and the assertion `0:18 (18 Sekunden)` passes
either way. A fractional fixture would be the honest way to close that, and it
is not done here.
