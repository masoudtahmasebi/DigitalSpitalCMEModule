# Epic P8 · Certificates & email — 7 h

**Week 5.** The learner-visible proof of participation. By design (ADR-0005) the
certificate does **not** depend on a successful EIV submission — that separation
is what makes the credentials-late fallback viable.

**Every task in this epic is behind the human review gate.**

> **Dependency:** the signature/stamp asset must be supplied by MEDICE before this
> phase starts (roadmap §12 item 3). The ADHS SMTP configuration file is needed
> for P8-02 (roadmap §12 item 4).

---

### P8-01 · Certificate PDF generation

- **jira:** _(unassigned)_
- **Estimate:** 2.5 h · **Week:** 5 · **Depends on:** P4-05
- **Review gate:** human — certificates

**Context**
A CME certificate is a document a physician submits to their Landesärztekammer.
Every field on it is a factual claim about an accredited event, so a wrong value
is a compliance problem rather than a formatting defect.

**Scope**
- PDF from a template carrying: participant name, EFN, course title, VNR, CME
  points and category, accreditation body, event date, Fortbildungsnummer, and
  the MEDICE signature/stamp asset.
- Values read from the completion record and the enrolment snapshot, never from
  the live course record.
- Deterministic: regenerating a certificate for the same completion produces the
  same document.

**Acceptance criteria**
- [ ] Every field matches the completion record and enrolment snapshot exactly
- [ ] A later change to the course's CME points does not alter an already-issued
      certificate
- [ ] Regeneration is byte-stable for the same completion
- [ ] German characters, long names and long course titles render without
      truncation or overflow
- [ ] The certificate is issued on completion regardless of EIV submission status

### P8-02 · Project-bound SMTP configuration

- **jira:** _(unassigned)_
- **Estimate:** 1.5 h · **Week:** 5 · **Depends on:** P2-01
- **Review gate:** human — certificates

**Context**
Roadmap §2: SMTP settings come from the existing ADHS platform PHP configuration
and are bound per project, so each customer's mail leaves from their own sender
rather than a shared one.

**Scope**
- Encrypted-at-rest SMTP credentials on the project record, seeded from the
  handed-over ADHS configuration.
- Resolution at send time from the project owning the course.
- Mailpit as the local target in development.

**Acceptance criteria**
- [ ] Credentials are write-only, encrypted at rest, and never returned by any
      endpoint
- [ ] Mail is sent using the credentials of the project that owns the course, not
      a global default
- [ ] A project with no SMTP configuration fails loudly at configuration time,
      not silently at send time
- [ ] Development sends to Mailpit and can never reach a real recipient

### P8-03 · Delivery and retry

- **jira:** _(unassigned)_
- **Estimate:** 1.5 h · **Week:** 5 · **Depends on:** P8-01, P8-02
- **Review gate:** human — certificates

**Scope**
- Send the certificate to the learner on completion, with the PDF attached.
- Durable retry with backoff; distinguish permanent rejection (invalid address)
  from transient failure.
- Delivery status persisted and visible in the P9 participant list.

**Acceptance criteria**
- [ ] A transient SMTP failure is retried; a hard bounce is not retried forever
- [ ] Retries survive an API restart
- [ ] A failed delivery never blocks the certificate being downloadable (P8-04)
- [ ] Delivery status is queryable per participant
- [ ] The email body contains no EFN

### P8-04 · Certificate download endpoint

- **jira:** _(unassigned)_
- **Estimate:** 1.5 h · **Week:** 5 · **Depends on:** P8-03
- **Review gate:** human — certificates

**Context**
Email delivery fails for reasons outside our control — full mailboxes, corporate
filters. Download is the path that always works, which is why P8-03 explicitly
does not gate it.

**Scope**
- Authenticated download scoped to the owning learner.
- Tenant-scoped; admins download within their own scope only.

**Acceptance criteria**
- [ ] A learner can download only their own certificate
- [ ] A certificate URL is not guessable and does not expose an enumerable
      identifier
- [ ] Download works even when email delivery has permanently failed
- [ ] A request for another learner's certificate returns 404, not 403 —
      existence is not disclosed
