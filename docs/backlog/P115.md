## P115-01 · The sidebar and the heading numbered the same module differently

**Status:** done · widget only, no schema, no API

Not reported — found in the client's screenshot while reading it for something
else. The outline says **Modul 4 – Psychotherapie & Coaching**; the heading
under the video says **Modul 5 – Psychotherapie & Coaching**; the progress card
says **Modul 5 von 5**. Same chapter, same module, two numbers.

Two code paths answered it:

| Surface                 | Numbered from                                                         |
| ----------------------- | --------------------------------------------------------------------- |
| heading under the video | `locateContent(props.course, …).moduleIndex` — walks `course.modules` |
| the outline             | `index` in `props.state.modules.map(…)` — the enrolment state         |

Both lists are ordered by `modules.ordinal` in their own queries, so they agree
until their **membership** differs — and the catalogue and the enrolment state
are separate reads with nothing requiring them to hold the same modules.

That is `CLAUDE.md` §4 invariant 6 in miniature: two implementations of one
fact, free to disagree. A module number is how a physician says where they are,
and it appears on a screen next to a CME progress figure.

**Fixed** with `moduleNumber(course, moduleId)` in `player.ts`, beside
`locateContent` and answering the same question for a module rather than a
content. The sidebar asks it instead of counting its own rows, so the two agree
by construction.

Three tests in `player.test.ts`; the first is the one that matters — for every
module in the course, `moduleNumber` and `locateContent` return the same index.
No test had ever stated that property.

**Not root-caused.** Which of the two lists is missing a module cannot be
determined without the production rows. The fix makes the symptom impossible
either way, but the divergence itself is still open — see below.

## P115-02 · The Zusammenfassung had no field to fill it in

**Status:** done · console only

There was no way to set it. The player renders that paragraph from the content's
`body`, and only for a video:

```ts
const body = props.lesson.kind === "video" ? (props.lesson.body ?? "") : "";
```

The console offered the body field for `text`, `details` and `material` — every
kind **except** `video`. Exactly inverted: the one kind whose body the learner
sees is the one kind the form would not let an author write.

The comment directly above that condition already said it, from the last time
this happened one kind along:

> An exposed field nobody can fill is the same as no field.

That fix added `material` and did not ask which other kinds render a body. §9.2.

Nothing else needed changing — the column exists, `contentWriteSchema` accepts
`body` for every kind, and `contentProblems` requires it only for `text` and
`details`. A body on a video was always legal, stored and rendered. Only the
form was missing.

It is now labelled **Zusammenfassung** rather than "Text", with a hint naming
where it appears and what the learner sees without it (§9.4) — "Text" on a video
does not tell an author this is the paragraph under the player, which is most of
why an absent field read as an absent feature.

## Still open, and why each is waiting

### The three reports that need the new build first

- **`Diese Stellen fehlen noch: 0:06–0:07` persists.**
- **Forward seeking is possible.** There _is_ a server-side `seekCeilingSec` and
  the scrubber is meant to clamp to it. The reported gap was one second, so the
  ceiling was legitimately near the end and seeking there was allowed —
  consistent, but unconfirmed. Worth restating for the record: the clamp is a
  courtesy, not the gate. Coverage is the union of intervals validated
  server-side, so a skipped passage leaves a hole the percentage never fills.
  Nobody gains a point by dragging the scrub bar.
- **No way forward from a passed exam.** The control exists and renders when
  `onNext` is defined; `nextAfter` returned `undefined`. Needs the real course
  to diagnose.
- **Chapter nesting still unclear.** P106-03 added the indent and is in the
  undeployed set.

### The divergence under P115-01

`course.modules` and `state.modules` can hold different modules. P115-01 makes
that invisible on this screen; it does not make it correct. Worth an
integration test asserting the catalogue and the enrolment state agree on a
course's module set — the kind of check that would have caught this before a
screenshot did.
