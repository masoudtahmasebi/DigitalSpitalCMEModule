# P256 — Vollbild did not fill the screen

**Branch** `main`, from `d63aea3`.

## What was reported

15.10.2026, with a screenshot: _"in both mobile and desktop, when making video
full screen, it does not get full screen"_. The screenshot shows a black
screen, the picture at about 70 % of its height against the top edge, and no
control bar.

## P256-01 — the player goes fullscreen, not the frame

**Review gate:** none · presentation of the player; the watch gate is unchanged

Three causes, read from `VideoPlayer.tsx`:

1. `requestFullscreen` was called on the frame (`containerRef`), which holds
   the `<video>` but not the control row. Fullscreen had no controls, and no
   way out except Esc.
2. The video kept `max-h-[70vh]` in fullscreen: 504 px of a 720 px screen, at
   the top.
3. iPhone Safari has no element fullscreen, so the call was refused and the
   button did nothing. It now falls back to the video's native player
   (`webkitEnterFullscreen`); its scrub bar is already held by
   `enforceSeekLimit` on `seeking`, as in Picture-in-Picture.

Also: `document.fullscreenElement !== null` read `undefined` as "already
fullscreen" where the API is missing on `document`, and in the shadow root it
names the host, not the player. Both are now asked of the player's own root.

Fullscreen is now the whole player (frame + controls) as a column: the frame
takes every row the controls do not, `object-contain` so slide text is not
cropped.
