## P248-01 — the console agrees with the learner about "complete" and "watched"

**Review gate:** human (assessment) · closes ARCH-1, ARCH-2, ARCH-3, OOP-1

**Context**

CLAUDE.md §4 invariant 6: learner progress and admin reporting read the same
rollup. Three places do not.

- ARCH-1: `admin.service.ts:558` calls `summariseEnrolment` without
  `hasEvaluation`, so `completion.ts:188` (`?? true`) asks for an evaluation
  on a course that has none. P206-01 already ruled that without questions
  "entfällt dieser Schritt"; the `?? true` default was kept for callers that
  predate it. The admin list reports and never certifies, so passing the real
  value applies P206's rule rather than inventing one (§7 does not stop this).
- ARCH-2: `moderation.repository.ts:141` averages every `content_progress` row,
  counting quiz and text rows at their default 0 (`schema.ts:451`); the shared
  rollup weights videos by duration.
- ARCH-3: the pass comparison is written out at `assessment.service.ts:166`,
  `:246` and `learning.service.ts:1253`, beside `assessment.ts:100`.
- OOP-1: `learning.service.ts:1017` says `cmePoints` is the enrolment's
  snapshot; both callers pass `courses.cmePoints`.

Verified: ARCH-1, ARCH-2 lines re-read on `0208b64`. ARCH-3, OOP-1 from the
audit lane, to be re-read in the plan.

- `listParticipants` and the CSV read `hasEvaluationQuestions(course.id)` once
  and pass it.

  `summariseEnrolment(...).achievedWatchPercent`; the SQL average is removed.
- `meetsPassThreshold(score, threshold)` exported from `@ds/domain`, unit-tested
  at the boundary (equal, one below), called from all three sites.
- The comment is corrected.
