# P52 — What a QA pass through the local stack found

Raised 11.08 by a QA run against the local stack, which began by discovering
that "the system is running locally" was not true: there was no Docker daemon,
no database and no API. Everything below was found while bringing it up.

---

## P52-01 · `/health` was blind to Redis · 1 h

**Status: done.**

Stopping `redis-server` and asking the API left it answering
`{"status":"ok"}`. The compose healthcheck fetches `/health` and treats any
200 as healthy, so with Redis dead the container reported healthy,
`depends_on` was satisfied, and a deploy went green on a process that could
neither cache JWKS nor count a rate limit. A gate that cannot go red is not a
gate.

- Both dependencies probed, in parallel, with a **separate catch each** — one
  shared catch would report a dead Redis as a dead database and send whoever
  is on call to the wrong container.
- `status: degraded` when either is down, which the already-existing
  `/health/ready` turns into a 503. That endpoint was correct; nothing was
  pointed at it.
- The compose healthcheck now polls `/health/ready`. `/health` deliberately
  keeps answering 200 with a degraded body — it is a diagnostic and the body
  is the answer — and `health.controller.ts` already documented why.
- `/health/live` still ignores dependencies, so a Redis outage cannot
  restart-loop the fleet.

`health.service.test.ts` is new; there was **no test for this module at all**,
which is how a whole dependency went unchecked. Every case in it is a failure
case.

## P52-02 · A dev Keycloak stub · 2 h

**Status: done.** See the file header in `apps/api/src/dev-keycloak.ts`.

Two of five seeded projects are `identity_provider = keycloak` and could not
be exercised without Docker. The stub is a **real OpenID provider with a real
keypair** — the API's validation is untouched, and every refusal was produced
on purpose to prove it (wrong audience, expired, wrong issuer, tampered
signature, malformed, absent).

The containment claim in its header was written first and then checked, and it
was wrong: `pnpm deploy` copies the whole compiled `dist/`, so the stub was
being baked into the API image. The `api` stage now removes it.

## P52-03 · Every seeded course is shaped like a real course · 3 h

**Status: done.**

### What was wrong

No seeded course had **two modules each with two or more chapters**. The shapes
were one of two degenerate kinds:

| Course                | Shape                     | What it could not exercise     |
| --------------------- | ------------------------- | ------------------------------ |
| `adhs-akademie-adult` | 5 modules × 1 chapter     | gating _within_ a module       |
| `ds-cme-demo`         | 3 modules, 4 chapters     | gating within a module, mostly |
| `ds-ohne-punkte`      | 2 modules × 1 chapter     | gating within a module         |
| `dscourse`            | **1 module** × 5 chapters | gating _between_ modules       |

`courseChapterSequence` gates within a module and between modules on different
branches. Every fixture exercised one branch or the other, and none exercised
both — so a break in either could reach a physician.

### What changed

`ds-cme-demo` is now 3 modules of 2, 3 and 2 chapters; `ds-ohne-punkte` is
2 × 2; `dscourse` is 2 modules of 3 and 2. `adhs-akademie-adult` is
**deliberately unchanged** — it mirrors the real ÄKWL Anerkennungsbescheid, and
reshaping it to satisfy a test would make the fixture stop matching the
document it exists to represent. It is exempted by name, with the reason, in
`scripts/check-seed-structure.mjs`.

### Two real defects the deeper fixtures found immediately

**A 500 on the last screen of the course.** `ds-demo`'s seeder placed the quiz
in _every chapter of the last module_ and gave questions to only one of them.
An empty quiz is not cosmetic: `assessment.service.ts` throws `content=… is a
quiz with no questions configured`. It was right by coincidence for as long as
every last module had exactly one chapter. Now placed in the last chapter of
the last module, in both seeders.

**A refusal that sent the learner to the wrong place.** A locked chapter
answered _"Diese Inhalte werden nach Abschluss der vorherigen **Module**
freigeschaltet"_ — but the gate is a chapter sequence, and what usually blocks
a learner is the chapter immediately above, in the same module. Correct only
while every module had one chapter. Now _"der vorherigen **Kapitel**"_.

Neither was reported by anyone. Both were unreachable until a fixture had the
shape that produces them, which is the argument for the check below.

### The check

`scripts/check-seed-structure.mjs`, run automatically at the end of
`pnpm db:dev:reset` and standalone whenever wanted.

It **reads the database rather than the seed source**: there are three seed
files with three different loops and a fourth will be written. Parsing them
would check the code that exists rather than the courses that result — the
`role-matrix.mjs` mistake, where a checker silently covered five of nine
screens and reported on all nine.

Not in `pnpm verify`, deliberately: verify must run on a laptop with no
Postgres, and every other check in it is static.

**It found its own bug on first run.** Pointed at `ds_app`, RLS returned zero
rows and it reported _"no courses found — is the database seeded?"_ about a
database seeded three times a second earlier. That is CLAUDE.md §9.6 happening
to the checker instead of the product. It now asks `pg_roles` whether the
connection bypasses RLS and says which of the two situations it is in.

### Acceptance criteria

- [x] Every non-exempt course has ≥2 modules, each with ≥2 chapters
- [x] Every chapter has something completable in it — materials do not count,
      because a Mediathek download has no completion event and a
      materials-only chapter would lock everything after it forever
- [x] Exactly one quiz per course, in the last chapter of the last module,
      with questions
- [x] The check goes red on a shallow module, on a materials-only chapter, and
      on an RLS-blinded connection — all three verified by breaking them
- [x] The check runs where the developer is, not only in CI
- [x] Full journey re-run on the deepened course: 7 chapters in order, gate
      refusing each locked chapter, quiz, evaluation, EFN, completion, and a
      5411-byte PDF 1.7 certificate
