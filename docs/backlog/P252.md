# P252 — two descriptions, because a card and a page are not the same text

Closes **DEP-47** (_Backend – Fortbildungen > Inhalte & Darstellung_), filed by
Philipp on 06.10.2026.

---

## What was reported

> There are two description texts for a Fortbildung. The first is displayed on
> the overview page listing all fortbildung courses: /dscme. … We also need a
> second description text for the detail page … Currently, the same text is
> displayed on both URLs.

True, and derivable from source. `courseDetailSchema` **extends**
`courseSummarySchema` (`catalog.dto.ts:127`), so both inherit the one
`description`. `CourseList.tsx` renders it on the card; `OverviewTab.tsx:51-53`
renders the same string under _Beschreibung der Fortbildung_. There is one
column, `courses.description`, and two screens with different jobs reading it.

That is **not** §9.10b. One value with two readers is the defect §9.10b names;
this is two values that were never given two homes. A catalogue card wants a
sentence that makes somebody click; a detail page wants the paragraph that says
what the Fortbildung covers. Writing one string that does both is the author's
problem, and it is the problem the ticket is about.

## Scope

- `courses.description_detail`, nullable, migration `0057`.
- On the DTO it is `descriptionDetail`, added to **`courseDetailSchema` only**.
  The catalogue list never renders it, and a field in `courseSummarySchema`
  would be bytes on every card of every page for nothing.
- `OverviewTab` renders `descriptionDetail ?? description`.
- Admin form: the new field directly above **Lernziele**, as asked.

### Why a fallback and not a second required field

An unset `description_detail` must leave the detail page exactly as it is
today, because MEDICE's live course has a paragraph there and a migration that
blanks it is a content loss nobody asked for. So the column arrives null for
every existing row and the widget falls back — today's behaviour, byte for
byte, until somebody types something.

The form says so (§9.4): the hint under the new field states that the
Übersichtsseite text is used while it is empty. An author who leaves it blank
has to be able to find that out from the screen rather than from a support
call.

### The labels, verbatim where they can be

| Field               | Label                              | Hint                                                                      |
| ------------------- | ---------------------------------- | ------------------------------------------------------------------------- |
| `description`       | **Beschreibung (Übersichtsseite)** | "Erscheint auf der Übersichtsseite für alle Fortbildungen als Introtext." |
| `descriptionDetail` | **Beschreibung (Detailseite)**     | names the fallback                                                        |

The hint is the sentence the ticket dictates. The ticket attaches it to "this
change", directly after describing the **new** field — but the sentence says
_Übersichtsseite … als Introtext_, which is the **old** field. Applied to the
old field, on the sentence's own words. Flagged on the ticket rather than
decided silently; it is one line to move if the reading is wrong.

`Übersichtseite` in the ticket's label is corrected to `Übersichtsseite` —
the ticket's own hint spells it that way two lines down.

## The guard that caught what review would not have

`pnpm verify` went red on `authoring.integration.test.ts:2152`:

```
courses.description_detail is neither copied by cloneCourse nor listed as
deliberately reset. Decide which, in the repository and here (P178-02).
```

P178-02 enumerates every column of `courses` from `information_schema` and
requires each to be in one of two lists. A new column is therefore a decision
somebody has to make out loud, and the default is a failing build rather than a
clone that silently drops a field.

Copied, and the reason is the line between the two lists: the RESET list is
accreditation identity (`vnr`, the Bescheid's window) and things a copy must not
inherit (`status`, `content_locked`). A description is presentation — the thing
a clone exists to avoid retyping.

## A promise that is now true

`de.course.descriptionHint` on the **creation wizard** already read "die
ausführliche Beschreibung der Detailseite wird später bearbeitet". It was
describing a field that did not exist — §9.2 in a hint rather than a control.
It is left exactly as it is, because as of this ticket the sentence is simply
correct: the wizard takes the overview text, and the detail text is edited
afterwards on this form.
