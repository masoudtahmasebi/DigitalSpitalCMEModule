# P133 — The number on the screen, and the design that was three screens deep

**Status:** both built. The second is a first pass over the shared primitives,
not the whole console — what is and is not covered is listed below.

---

## P133-01 — "up to 2 GB" on a server that accepts 5

Reported from the screen:

> _"the library upload in course still says `MP4 or WebM, up to 2 GB`"_

True, and mine. P129-01 raised `UPLOAD_MAX_BYTES.video` from 2 GiB to 5 GiB so a
3 GB lecture could be uploaded, and the sentence that tells an author what the
limit is was a **literal** — written out twice in `de.ts` and twice in `en.ts`.
Nothing connected the two, so the console went on refusing, in words, a file the
API would have taken.

CLAUDE.md §9.3 in its plainest form: the rule moved and the sentence stating the
rule did not, because nothing called anything.

`uploadLimitLabel(purpose)` is the connection, and it lives in `@ds/domain` beside
the constant it reads. Binary units with a decimal label — 5120 MiB reads "5 GB",
the way a file manager has always shown it, rather than the more accurate and
less true "5.37 GB".

Interpolated strings rather than functions of the locale table, deliberately:
`overlay` translates strings and leaves functions in German, so a hint that became
a function would have silently stopped being English — which is the language the
client was reading when they found this.

The check is three cases in `language.test.ts`. Two assert the derived label is
present in both locales; the third asserts each hint contains **exactly one** size
claim, because the first two pass on "up to 5 GB (formerly 2 GB)" and it is the
third that makes them evidence. Watched to go red by writing "2 GB" back into
`en.ts`, which is exactly the regression that shipped.

## P133-02 — Why the console still looked the same

> _"i don't see any design change in the admin panel, only media library upload
> section"_

Correct, and the reason is not a stale build: the Mediathek upload panel shipped
in `e64c7bf`, which reached production for the first time in today's deploy. Being
able to see it is proof the new build is live. The console looked unchanged
because **only three screens had been redesigned** — the quiz editor, the media
library, and the creation wizard — and each of those is somewhere you have to
navigate to. The shell, the lists, the tables, the forms and the twelve other
screens were untouched, and those are what "the admin panel" is.

Redesigning screen by screen was the mistake. The console's look lives in three
files that every screen inherits, so this pass changes those instead:

- **`ui.tsx`** — one `FIELD_SKIN` and one `CONTROL_FOCUS` constant rather than
  nine copies of a class string; buttons and inputs at `rounded-lg` with a
  brand-coloured focus ring; badges as ring-bordered pills; panels and tables at
  `rounded-xl` on a white surface with a shadow; table headers in small caps.
- **`page.tsx`** — the screen's own name a step larger and tighter, so a page
  reads as having a top rather than as a list of equals; roomier empty states.
- **`App.tsx`** — a wider sidebar, quieter group headings, and the active item as
  a crimson pill with a soft glow; a keyboard focus ring that is visible against
  the dark rail; the course rows with hover and a link that looks like one.

**The table-padding defect this found.** Cell padding was written out as
`px-3 py-2` on fifty `<td>`s across eight screens, so raising the header's padding
here left every body cell misaligned and there was no one place to fix it. It is
the table's now — an arbitrary variant on the element, which is more specific than
a utility on the cell, so a row cannot disagree with its own header. Same
reasoning as the surface living in `Table` rather than at each call site.

### What this pass does not do

Named rather than implied: the individual screens keep their existing layouts.
Organisation, Konten, Zugänge, Teilnehmende, Bescheinigungen, Punktemeldungen,
Erscheinungsbild, Texte, Sicherheit and the course-detail tabs now inherit the new
controls, surfaces and rhythm, and none of them has been redrawn. If a particular
screen is the one that reads badly, it is worth naming it rather than another
sweep.
