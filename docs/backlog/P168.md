## P168-01 — The seek ceiling is now a rule of the API

### What was wrong

The question in the report is the correct one, and the answer is that they
_could_ — not in the player, in the record.

`validateSegments` refused a segment past the **duration** (`beyond_duration`)
and one claiming more playback than wall-clock time allowed
(`faster_than_wallclock`). Nothing refused one past the **seek ceiling**. The
ceiling was computed from the stored union, returned to the client, and enforced
by `isSeekAllowed` in the player — and never checked on the way back in.

So `POST /courses/{slug}/contents/{id}/progress` with
`{"segments":[{"startSec":1400,"endSec":1489}]}` against a video nobody had
opened was **accepted and stored**. "Vorspulen ist nicht möglich" was a property
of the renderer, which is CLAUDE.md §4 invariant 1 exactly: the client is a
renderer and may never be the source of truth for anything deciding a CME point.

`Verified:` `packages/domain/src/watch.ts` `rejectionReason` — it takes
`(segment, durationSec)` and nothing else; the new cases in
`watch.test.ts` were watched red before the fix.

### What it is now

`SegmentValidationOptions.previousSegments` — the enrolment's stored union for
that content. When it is given, a segment beginning more than
`CEILING_ACCEPTANCE_TOLERANCE_SEC` (2.5 s) past the furthest point that union
reaches is rejected as `beyond_ceiling`.

Three details carry the weight:

1. **The ceiling advances within a report.** One flush carries a run of
   consecutive intervals — `[100,115]`, `[115.2,130]`, `[130.1,145]` — and each
   begins past what the _stored_ record reaches. Against a ceiling fixed at the
   stored maximum, everything after the first interval is refused and a learner
   watching normally is credited one heartbeat in four. It advances by what was
   **accepted**, so a batch still cannot walk itself anywhere.
2. **The hop is charged to the wall-clock budget.** Without that, the tolerance
   is free: a client posting `[t, t+0.1]` every 2.5 s walks 2.6 s of video per
   0.1 s of budget — twenty-six times real time — and every hole it leaves is
   inside `fillSamplingGaps`' limit and bridged into full coverage. Charging the
   gap makes a hop cost exactly what watching it would have cost.
3. **`undefined` is not `[]`.** Omitted means "the caller holds no record", and
   the check does not run — the admin re-scoring path and the tests that predate
   this. `[]` means "nothing watched", and correctly pins a first report to the
   start of the video.

### What was deliberately not done

The tempting fix was the generous one: they reached the end, so bridge the hole
and credit it. Every version of that credits media time nobody reported, on the
strength of wall-clock time — and wall-clock time accumulates while a page sits
open. A ten-minute video, an hour-old tab and one five-second fragment at 09:55
would be a completed Fortbildung. That is `watchedPercent` becoming
max-position by a longer route, which is the one thing §4 invariant 5 exists to
prevent. It is asserted as a case of its own ("refuses it however long the page
has been open") so the next person to have the idea meets a red test.

`fillSamplingGaps` is therefore **unchanged**, limit included. With forward
jumps refused, the only holes that can form below the furthest point are
narrower than the tolerance, which is well inside what it already bridges.

### Why refusing does not strand anybody

- `resumeAtSec` is already capped at `seekCeiling(storedSegments)`, so a reload
  returns the learner to the last second the server agrees they watched — never
  past it. (`learning.service.ts`, the cap predates this ticket.)
- A failed flush is re-sent: `WatchTracker.restore` puts drained intervals back.
- A throttled tab is bridged in the tracker (P166-01) while it is still an
  observation rather than a claim.

`Assumed:` that no stored enrolment has a `watched_segments` union whose holes
are wider than the tolerance _and_ a learner still mid-video. Such a record —
written before today, when the jump was legal — would have its later reports
refused until the learner rewinds into the hole, which the gap list already
tells them to do. Not traced against production data; the query would be a hole
wider than 2.5 s below the maximum on an enrolment with `completed_at IS NULL`.

### The class (§9.11)

The shape is **a rule the client is told about and the server does not check**.
Searched for the others: `seekCeilingSec` (this ticket),
`requiredWatchPercent` and `passThresholdPercent` (both re-read server-side in
`deriveState` / `gradeAttempt`), `resumeAtSec` (advisory, credits nothing),
`lastPositionSec` (client-reported, stored, and already capped at the ceiling
everywhere it is used — the comment at `resumeAtSec` says why). The one that was
missing is the one this fixes.

## P168-02 — The Punktemeldung has a button on the course

The course-detail progress card knew the physician had finished — the green
"Fortbildung abgeschlossen" banner is drawn from `courseComplete` — and answered
"and now?" with a sentence naming a tab: _"Sie finden sie unter
‚Zertifizierung'"_. The form is not on that tab; #60 moved it off deliberately,
and the tab is five prose sections about the accreditation.

So the only route to the Punktemeldung was **sitting the exam again**, which is
what the client found and is also the wrong act.

**CME-Punkte geltend machen** now sits under that sentence, on the inline card
and on the floating panel that replaces it below `sm` — a button added to only
one of the two is a button no phone has. It is offered under exactly the
condition `POST /completion` accepts on (`courseComplete`, completion still
open) and takes the Evaluationsbogen first when that is outstanding, because the
API refuses a completion without one and the refusal would otherwise arrive
after the EFN had been typed. Same two decisions as the quiz-passed screen's
button, not a second opinion about them.

## P168-03 — The catalogue tells its three states apart, and offers the way on

A certified course differed from one nobody had ever opened by one word in a
button label — "Fortbildung ansehen" rather than "Zur Fortbildung". The
finished-but-unclaimed card carried a sentence with nothing to press.

- **CME-Punkte geltend machen** on the unclaimed card, which opens the course on
  the Punktemeldung.
- **"Abgeschlossen – Teilnahmebescheinigung verfügbar"** on the certified one.

`OpenIntent` (`apps/widget/src/intent.ts`) gains `"certify"` beside `"start"`
and `"resume"`, and `open-at="certify"` is accepted by `<ds-lms>` so a routing
host can carry the choice across its own navigation. It is a **request**: `App`
grants it only while the server says the course is complete and unclaimed, so a
stale card or a hand-written attribute lands on the course page rather than on a
form that would be refused (§9.2).

The union moved to its own module because it was written out in five places
across three layers that must not import each other; a fourth value is now a
compiler error rather than a screen that silently falls back.

## Acceptance criteria

- [x] A segment beginning past the ceiling the stored record implies is refused,
      named `beyond_ceiling` in the contract, the DTO and the SDK.
- [x] A run of consecutive intervals in one report is accepted.
- [x] Hopping the tolerance is bounded by the wall-clock budget.
- [x] The tolerance is below the smallest forward control the player offers
      (asserted against `SEEK_STEP_SEC` and `SEEK_JUMP_SEC`).
- [x] A finished, unclaimed course offers the Punktemeldung from the course
      page, on both the inline card and the mobile panel.
- [x] The catalogue offers it too, and marks a certified course as certified.
- [x] The intent is refused when the server has not finished the course.
- [x] Every new rule watched red: the ceiling (4 cases), the charge (1), the
      advance within a report (2), the card's gate (3), the catalogue's intent
      (1), the App's guard (1).

## Not done, and why

- **No e2e step yet.** `apps/e2e` needs a Docker daemon and this sandbox has
  none, so `pnpm test:e2e` could not be run at all — not for this change and not
  to check it against the existing journey. §9.13 says that is the layer that
  would notice a button nobody wired; the widget tests here assert the wiring
  (`App.route.test.tsx`), which is one layer short of a browser.
- **P162** — the 500 on deleting a non-empty module — is still open, tests
  written, product fix not. Stated here so it is not dropped silently (§11.12).
