## P211-01 — the two fields that never got the picker

`UploadField` has done exactly what is being asked for since P88-02: it uploads,
it offers **Aus Mediathek wählen**, and it still accepts a pasted URL so a
customer's own CDN keeps working. Four fields use it — video, poster, captions,
material.

Two do not, and they are the two the client was looking at:

| field                         | was                       |
| ----------------------------- | ------------------------- |
| `Titelbild (URL)` on a course | a 2000-character text box |
| `Foto-URL` on a Referent      | a 2000-character text box |

Both now use `UploadField`.

### The half that makes it work rather than look like it works

Offering the picker is not the fix on its own. An uploaded object is stored as
`s3://<key>` and **no browser can fetch that**. The lesson path has signed these
since P10-09 through `MediaResolver`, which also refuses a key belonging to
another customer — the bucket has no RLS to fall back on (§4 invariant 3).

The catalogue did not. `catalog.service.ts` passed `hero_image_url` and an
expert's `photo_url` straight through, which was correct while the only way to
fill those fields was to paste `https://…`, and becomes a broken image the
moment the field offers the library. Shipping the picker alone would have been
§9.2 exactly: a control whose result cannot work, and one that fails **silently**
— `<img src="s3://…">` renders nothing and logs nothing.

So the picker and the resolution are one change:

- `CatalogService` takes the **same** `MediaResolver` the lesson path uses —
  not a second one (§9.10b);
- `CatalogController` builds it the way `LearningController` does;
- `CourseRow` selects `customer_id`, so a key is checked against the course's
  own customer before it is signed. RLS already bounds the query; this is the
  defence in depth ADR-0002 asks for, and the same reason `media-url.ts`
  re-checks a key it was handed from a row.

### `mediaReference` now has one home

The refinement that accepts _either_ an absolute URL or `s3://…` lived private
inside `authoring.dto.ts`. `admin.dto.ts` validated the hero image with
`z.string().url()` and the expert photograph with the same. Copying the
refinement across would have been three lines and a second opinion that can
drift, which is §9.10b. It moved to `shared/media-reference.ts`; both import it.

### `purpose="poster"`, deliberately

`poster` is the platform's **image** purpose: it decides the accepted types and
the size ceiling, and `LIBRARY_KIND` maps it to the library's `image` family.
The name is historical — video posters were the first images the platform
stored. Adding an `image` purpose would be a contract change, an SDK
regeneration and a per-purpose policy entry for no difference an author could
see, which is the §3 trade this project keeps making badly in the other
direction.

### The labels were lying

`Titelbild (URL)` and `Foto-URL` named a text box. They are `Titelbild` and
`Foto` now — §9.4, say what the thing is. Both carry the size guidance the
client asked for.

**On that number:** _"Querformat, mindestens 1200 px breit — das Bild wird auf
die Fläche zugeschnitten."_ The **cropping** and the **half-width** are read
from `CourseHeader.tsx` (`object-cover`, `sm:grid-cols-2`). The **1200** is a
recommendation, not a measurement — the rendered box depends on the viewport,
and the layout export that would settle it is not in hand.

### Watched red

With the resolution reverted to the old pass-through, three of the four new
cases fail — including _"refuses a key belonging to another customer"_, which
returned another tenant's object key verbatim. That was unreachable before,
because nothing could write such a row; the picker is what makes it writable.

## What this ticket does **not** do

Each of these came out of the same call. None is absorbed quietly (§3).

### A copyable URL in the Mediathek

Asked for as _"like the wordpress uploader"_. It does not transfer, and the
reason matters: WordPress serves uploads from a **public** URL, and this
platform signs a **short-lived capability** per request. A "copy URL" button
would hand somebody a link that works for minutes and then 403s — a footgun
shaped like a feature.

Two honest options, and both are the client's call:

1. **Nothing.** Once every field offers the picker — which is this ticket — the
   copy step is the workaround it was invented to replace.
2. **A public prefix** for images the customer wants to use _outside_ the
   platform, served unsigned. That is a bucket-policy and data-protection
   decision, not a console change.

### The Wissenschaftliche Leitung and the Ausstellungsort, made optional

Philipp checked real Teilnahmebescheinigungen and neither carries them. This is
a **certificates** change, so §2's human review gate applies, and it collides
with an open question: the Kammer has not answered what the _Ort_ should be for
an online Fortbildung (`docs/show-stoppers.md`). Its own ticket, with the
Kammer's answer or an explicit decision to proceed without it.

### The catalogue for a DocCheck-only visitor

Philipp's first item: a visitor with only a DocCheck account should see the
overview and the detail page, and meet a dialog when they try to start. Masoud,
in the call: _"was this in the requirement? This is the first time I'm hearing
about this"_ — and _"right now the situation is this, we have to fix it
afterwards"_.

This changes **who may read the catalogue without an account**, which is auth
(§2) and new scope (§3). It is a ticket with a decision in it, not a fix.

### Sorting by the validity window

The call was working this out aloud and did not land. What the code does, read
today rather than guessed:

| question                        | answer                                                                       |
| ------------------------------- | ---------------------------------------------------------------------------- |
| what makes a course **visible** | `status = 'published'` **and** today inside `valid_from … valid_to` (P50-01) |
| what decides the **order**      | `created_at DESC`, title as tiebreak (P210-01, deployed 08.09)               |

So the behaviour Philipp saw — a course vanishing when he moved its dates — is
the validity window, working as designed. The order is _when it was created_,
not _when it becomes valid_. Sorting by `valid_from` instead is a one-line
change and a different product decision; it needs somebody to say which.
