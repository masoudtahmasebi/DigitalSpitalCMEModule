# P178 — The content lock, and the clone

**Raised by:** the client, 03.09.2026, with the course they built to find it:

> I have created a new course and named it as **DS Test Course**. […] added two
> modules. 1. first module had one video 2. Second module had a text content 3. In the second module, I have added questionnaire with 2 questions. 4. I
> have given the 6 punkten for this. 5. I have viewed the course, done with
> first video and done with the exam. I have not done the part to enter the
> EFN, so I was seeing the CME Punkten Machen button.
>
> **Scenario:** Now I have opened the course in verwaltung and I have added a
> new video content for module 1 — Earlier the video percentage was 100%, now
> it shows 75% completion only.

And the two features that answer it:

> we should lock the course contents with the modules which are created, when
> one of the user has completed the course and lock mode does this. […] When
> the course is locked, that means no more content can be added to the course.
>
> 2- Give a clone feature, if the user wants to clone one of the published
> course, which has similar content but different videos […] and the cloned
> course is not in lock mode, a course in lock mode can be unlocked and can
> also be cloned.

**Branch** `claude/education-platform-roadmap-3vgrqh`.

## What was actually happening

Nothing was broken, which is why it had survived. `courseWatchCoverage` weights
by duration across every video the course **currently** holds, so a course that
grows re-denominates everybody in it. The physician in the client's scenario had
finished the material and was one form away from claiming a CME point; a video
added to module 1 put them back under the watch gate, with no notification and
nothing on any screen to say why.

It is the same shape as P174-01 — a threshold raised under an unfinished learner
— with the protection missing. `alreadyCompleted` holds a **completed** enrolment
complete, and this physician had not finished the paperwork, so there was nothing
to hold.

The alternative fix — freeze each enrolment's denominator to the tree as it stood
at enrolment — is a second snapshot of the kind P171 and P174 spent a day
removing, and it would leave two physicians on one course graded against
different material with nothing on screen saying so. The client's reading is the
right one: **a Fortbildung somebody has completed is a fixed body of material.**
Change it and you are running a different event, which is what the clone is for.

## P178-01 — `courses.content_locked`

Migration `0050`. One boolean, and what it governs is deliberately narrow:

| Governed                                     | Not governed                                         |
| -------------------------------------------- | ---------------------------------------------------- |
| modules, chapters, contents                  | title, description, hero image, Thema, Altersgruppe  |
| a Lernerfolgskontrolle's questions + options | VNR, VNR password, validity window, points, category |
| the Evaluationsbogen                         | Referenten — presentation, like the title            |
| reordering, which is a structural edit       | publishing, certificate assets, EIV flags            |

The right-hand column is the reason this is not `status` and not derived from
`enrolments`. An Anerkennungsbescheid arrives weeks after a course is built and
carries the VNR every certificate has to print; a lock that refused it would make
the platform unable to record the number the Ärztekammer identifies the event by.
`status` answers "is this on the catalogue"; this answers "may its material still
change", and a course can be draft and locked or published and open.

**Set three ways**, all of which the client asked for: at creation
(`contentLocked` on `POST /admin/courses`), by an operator
(`PATCH /admin/courses/{slug}`, in **both** directions — a one-way door with no
key on any screen would be its own defect), and **automatically the first time an
enrolment on the course completes**, inside `markCourseCompleted`.

### Enforced where the decision is, offered nowhere else

- **The API refuses**, in `assertUnlocked`, reached from `slugForEdit` on every
  structural service method. `conflict`, not `forbidden`: the caller has every
  right to edit this course and the course is in a state that refuses. The
  German names the state, why it exists, and both ways forward (§9.4).
- **The console does not offer the controls.** `CourseStructureEditor` withholds
  every add, edit, delete and reorder on a locked course and states the rule
  once at the top; `QuizEditor` and `EvaluationEditor` render read-only views
  rather than forms with `disabled` on every field. A screen that took keystrokes
  and then answered 409 is `course_editor` (P38-02) and the self-reset button
  (P38-07) again.
- **The exam stays readable.** Looking is not an edit, and hiding the questions
  would take away what an author needs in order to decide whether they want a
  copy. The verb changes: „Fragen ansehen“, not „Fragen bearbeiten“.

### `scripts/check-content-lock.mjs`

The lock is a rule with **twelve call sites**, which is §9.3's exact shape:
`inviteStatus` and `invalidBrandingFields` were both exhaustively tested and
called from nowhere. The script derives the list of structural writes from the
**repository port** rather than from a list somebody maintains, so a new write
added to an unguarded service method fails there rather than by re-denominating
a physician. In `pnpm verify` and in CI.

Watched red three ways: the guard removed from one method; a new unclassified
write on the port; and the parser broken, which reports "green for the wrong
reason" rather than passing.

## P178-02 — Clone

`POST /admin/courses/{slug}/clone`. Copies the presentation and the whole tree —
modules, chapters, contents with their media references, the exam's questions and
options, the Referenten, the Evaluationsbogen. Copies **no people**: no
enrolments, no progress, no attempts, no certificates, which is what makes it
safe to edit.

Reset on the copy, each for its own reason:

| Field                     | Why                                                                                                                                                          |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `status` → draft          | a copy must not reach a catalogue because somebody clicked once                                                                                              |
| `content_locked` → false  | the client's requirement, and the point of the feature                                                                                                       |
| `vnr`                     | **two courses may not share one.** A Punktemeldung filed from a clone would credit the original's registration — a wrong statutory report against a real EFN |
| `fortbildungsnummer`      | the same argument one field over                                                                                                                             |
| `vnr_password_enc`        | a credential belongs to the registration it opens                                                                                                            |
| `valid_from` / `valid_to` | the accreditation window is the Bescheid's, and there is not one yet                                                                                         |

Points and category are **kept** as a starting value an operator confirms — the
`courses_published_cme_is_complete` constraint still refuses a published,
point-bearing course with no VNR, which is the right gate.

**A locked course can be cloned.** The source is read, never written. That is the
route out of the lock that does not touch material a physician was graded
against, and it is the second half of what the client asked for.

Retired questions are not copied: `retired_at` exists because an answered
question cannot be deleted, a clone has no attempts, and copying them would
resurrect a question an author had already replaced.

### The column lists, and the test that keeps them honest

The clone's `INSERT`s name columns explicitly, and the first run proved why that
rots: `course_experts (name, title, bio, photo_url)` against a table whose columns
are `role_label, name, institution, biography, photo_url`. That one failed loudly.
The version that would not is a column **added next year** and silently left out,
producing a copy quietly poorer than its source.

So `copies every column of every cloned table, or deliberately resets it` reads
`information_schema` and requires every column of all eight tables to be in
exactly one of two lists. A new column is in neither and it goes red until
somebody decides. Watched red by removing one column from the copied list.

## The stale sentence this turn also removed

`de.course.notRetroactive` told the operator, on the screen where the thresholds
are edited:

> Änderungen gelten nur für neue Teilnahmen. Bereits begonnene Teilnahmen
> behalten die Werte, die bei ihrem Start gültig waren.

That stopped being true in **P174-01**, when the client asked for the three gating
thresholds to come from the course. `findEnrolment` reads all three from `courses`
today. The screen was stating the opposite of what the product does, in the one
place where the difference decides whether somebody may proceed. Renamed to
`thresholdReach` and rewritten, together with `CourseSettings.tsx`'s header
paragraph, which made the same claim (§11.9, §11.14).

## Acceptance criteria

- [x] A lock settable at course creation, by an operator, and automatically on
      the first completion.
- [x] Locked means the API refuses every structural write — one integration test
      per route, plus reorder.
- [x] Course-level fields stay editable while locked; asserted, not assumed.
- [x] Unlockable, and the refused edit then goes through.
- [x] The console offers no control the API would refuse, and says why and where
      the two remedies are.
- [x] A clone of a locked course: unlocked draft, whole tree, no participants,
      no VNR.
- [x] The clone is editable immediately, and the source is untouched.
- [x] A mechanical check that a new structural write cannot skip the guard.
- [x] Every rule watched red: the lock read, the auto-lock write, the guard per
      method, the port census, the clone's VNR reset, the column census, the
      console's provider.
