# Epic P0 · Foundations & AI-first setup — 10 h

**Week 1.** Everything downstream is generated against the specs, schema and pure
logic established here, so this phase is deliberately front-loaded with the
things that are expensive to change later: the tenant isolation model, the
hierarchy schema, and the standing rules.

**Demo at end of phase:** `docker compose up` brings the stack up, migrations and
seed run clean, and `pnpm test` passes against the pure domain core.

Per roadmap §13, DEP-2 and DEP-3 fold in here as foundation tasks.

- **Review gate:** none

**Context**
Seven workspaces built and tested on every generated commit. The scaffold has to
be right once, because retrofitting shared config across seven packages later is
pure waste.

**Scope**
- pnpm workspaces + turborepo; `tsconfig.base.json` with `strict: true`.
- `packages/config` — shared eslint, tsconfig and tailwind presets consumed by
  every other workspace rather than duplicated.
- Workspace stubs: `apps/api`, `apps/widget`, `apps/admin`, `apps/eiv-harness`,
  `packages/domain`, `packages/sdk`, `packages/config`.
- `.github/workflows/ci.yml` — install → lint → typecheck → test → build, with
  turbo cache.
- `.gitignore`, `.editorconfig`, `.nvmrc`.

**Acceptance criteria**
- [ ] `pnpm install && pnpm build && pnpm lint && pnpm typecheck && pnpm test`
      succeeds from a clean checkout
- [ ] `strict: true` is inherited by every workspace; no workspace opts out
- [ ] CI runs the same commands as a developer runs locally — no CI-only steps
- [ ] Adding a new workspace requires no change to the root lint or tsconfig

- **Review gate:** none

**Context**
Integration tests run against a real PostgreSQL, never mocks (`CLAUDE.md` §6),

**Scope**

- `infra/keycloak/realm-export.json` — a `ds-dev` realm mirroring the shape of the
  MEDICE ADHS realm: one confidential client, one public client, the four roles,
  and two test users.
- `.env.example` documenting every variable, with no real secret in it.
- Root scripts: `pnpm infra:up`, `infra:down`, `infra:logs`, `infra:reset`.

**Acceptance criteria**
- [ ] `pnpm infra:up` reaches healthy on all four services from a cold start
- [ ] The Keycloak dev realm imports automatically; a test user can obtain a token
      via the token endpoint with no manual console configuration
- [ ] `pnpm infra:reset` returns the stack to a known-empty state
- [ ] `.env.example` is complete enough that a fresh clone needs no undocumented
      variable

### P0-04 · Schema v1 with row-level security

- **jira:** _(unassigned)_
- **Estimate:** 2.5 h · **Week:** 1 · **Depends on:** P0-03
- **Review gate:** human — tenant isolation
- **Implements:** ADR-0002

**Context**
The full hierarchy from roadmap §3, plus the learner, assessment and compliance
tables. This is the single most expensive thing in the project to change later,
and the RLS policy shape defined here is what P10-02 verifies.

**Scope**
- `db/migrations/0001_init.sql`, plain reviewable SQL:
  - Hierarchy: `customers → departments → projects → courses → modules →
    chapters → contents`
  - Project config: encrypted `smtp_settings`, branding, Keycloak realm/issuer/
    audience binding
  - Course compliance: `vnr`, encrypted `vnr_password`, `cme_points`,
    `cme_category`, `accreditation_body`, `valid_from`/`valid_to`,
    `fortbildungsnummer`, `pass_threshold_percent`, `required_watch_percent`,
    `retry_policy`
  - Learner: `users`, `efn_profiles`, `enrolments`, `content_progress`
    (incl. `watched_segments jsonb`)
  - Assessment: `quiz_questions`, `quiz_options`, `quiz_attempts`, `quiz_answers`,
    `evaluations`, `evaluation_responses`
  - Compliance: `certificates`, `eiv_submissions`, append-only `audit_log`
- `customer_id uuid not null` denormalised onto every tenant-scoped table.
- Identical RLS policy shape on every such table, with `enable` **and** `force`.
- Roles `ds_migrator` (owns schema) and `ds_app` (used by the API, **not**
  `BYPASSRLS`, not table owner).
- Drizzle schema mirroring the SQL exactly; the SQL is authoritative.

**Acceptance criteria**
- [ ] Migration applies to an empty database and is idempotent to re-run detection
- [ ] Every tenant-scoped table has `customer_id not null`, RLS enabled **and**
      forced, and the identical policy expression
- [ ] With `app.customer_id` set to customer B, every table returns zero rows of
      customer A's data
- [ ] An insert carrying a `customer_id` other than the session's is rejected by
      the `with check` clause, not by application code
- [ ] `ds_app` cannot bypass RLS even when it is the connecting role
- [ ] All timestamps are `timestamptz`; all percentages are integers 0–100
- [ ] `audit_log` rejects `update` and `delete`

**Additional DoD**
- [ ] The Drizzle schema and the SQL are verified to agree by a test, not by eye

### P0-05 · packages/domain skeleton and test harness

- **jira:** _(unassigned)_
- **Estimate:** 1 h · **Week:** 1 · **Depends on:** P0-02
- **Review gate:** none

**Context**
`packages/domain` is what makes the rest of the codebase safe to generate. It
must be provably free of I/O, framework imports, clock reads and randomness —
time is always an argument.

**Scope**
- Package with zero runtime dependencies; vitest configured.
- Public type surface for the hierarchy, progress, assessment and EIV concepts.
- A lint rule or test that fails the build if the package imports anything
  outside itself.

**Acceptance criteria**
- [ ] `packages/domain` has an empty `dependencies` block
- [ ] A test fails if the package reads `Date.now()`, `Math.random()` or performs
      any I/O
- [ ] The package builds and tests standalone with no infrastructure running

### P0-06 · Seed the real ADHS course

- **jira:** _(unassigned)_
- **Estimate:** 1.5 h · **Week:** 1 · **Depends on:** P0-04
- **Review gate:** none

**Context**
Roadmap §11 lists "content not ready for launch" as a risk, mitigated by seeding
from week 1. Every later phase demos against this seed, so it must reflect the
real MEDICE structure rather than lorem ipsum.

**Scope**
- `db/seed/adhs.ts` — MEDICE → ADHS → "ADHS Plattform" → "ADHS bei Erwachsenen",
  with real module and chapter titles including "Modul 3 – Pharmakotherapie" and
  "Kapitel 3 – Nebenwirkungen".
- Course compliance values set to the MEDICE configuration:
  `pass_threshold_percent = 70`, `required_watch_percent = 100`.
- One complete quiz with single-choice and multi-choice questions, and one
  Evaluationsbogen.
- Two seeded learners at different progress states, so rollup is visibly
  non-trivial from day one.

**Acceptance criteria**
- [ ] `pnpm db:seed` is idempotent — running it twice leaves one course, not two
- [ ] Seeded data satisfies every RLS policy and foreign key without disabling
      anything
- [ ] German titles and terminology match the approved layout exactly, including
      capitalisation
- [ ] At least one seeded learner is mid-course, with partial watched segments
