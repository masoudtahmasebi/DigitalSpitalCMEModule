# P157 — Choosing the register, without letting a browser name one

The first slice of the EIV/certificate harness. Answers the question P152 §4
left open, in the form the client gave it:

> i want to be able to test either against the prod or test, i know this already
> exists, i can not choose which backend, and enter a test vnr, test efn

Branch `P157-eiv-environment`, from `origin/main` at `bf49fb8` (PR #45 merged).

## What already existed, and what did not

P152's inventory holds the detail. In one line: a course-level EIV diagnostic
has existed since P103-01 — `POST /admin/courses/:slug/eiv/check`, steps
`authenticate | event | reported`, a write-only VNR password encrypted at rest,
and a panel already mounted in the course settings screen. It reports which
endpoint and which tier it reached.

What it could not do is **aim**. `EIV_BASE_URL` is one deployment-level value,
so the check went wherever the installation points and there was no way to ask
"and does it work against the test register?"

## The danger, and the shape that removes it

A control that picks the register is a control that can pick the **live** one,
and a Punktemeldung cannot be unfiled — only withdrawn, which leaves its own
entry on a physician's record.

So the browser never names an address. It sends one of two words:

| Word         | Resolves to                                         |
| ------------ | --------------------------------------------------- |
| `configured` | whatever this installation is pointed at            |
| `test`       | `backend-test.eiv-fobi.de`, EIV's own test register |

`eivEnvironmentUrl` in `@ds/eiv-client` turns the word into a URL from a list
that module owns. There is no branch that returns its second argument except for
`configured`, which is the installation's own setting and was never the caller's
to choose — so a body carrying `https://attacker.example` or the live register
changes nothing. Tested, and watched red when the resolver was made to pass the
caller's URL through.

`test` resolving to the test register **whatever the installation is pointed
at** is what makes this safe to run from a production installation: an operator
can rehearse without touching the register their customers' points go to.

## What this slice does not do

It does not file a Punktemeldung, and it does not generate a certificate. The
route it extends still reaches the two read-only capabilities and never
`submit` — verified by grep, not by its comment, in P152. The filing and the
watermarked diagnostic certificate are the next two slices, and the filing one
carries the rule that a synthetic EFN is refused against anything but the test
or mock tier.
