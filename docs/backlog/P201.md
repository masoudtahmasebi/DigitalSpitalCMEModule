# P201 — The console never said why a course was not reaching learners

**Raised by:** the client, 07.09.2026 — _"I have created a course Medice Test
Course, I don't see it in the courses list. Did you set any limit on the course?
… only 7 of the courses are shown, what is going on??"_

---

## I answered wrong first, and that is the point of this ticket

I said the missing course was a draft. The client sent back a screenshot of it
open in the console: **"This course is published and visible to participants."**

The lesson is not that I guessed badly. It is that **guessing was the only thing
available**, to me and to them: there are five reasons a course does not appear
in the Fortbildungsbereich, the console shows none of them, and the screen that
holds the answer had been asked the question and said nothing.

## The facts, which are not what was reported

- `admin.repository.listCourses()` is `select … from courses order by title`.
  **No limit, no filter, no pagination.** The admin list shows every course of
  the chosen customer, always. The 9 rows in the client's screenshot are all 9
  courses.
- The learner catalogue is the list that shows 7. Its page size defaults to 10,
  so 7 is not a page boundary either — it is a filter.
- `whereFor` in `catalog.repository.ts` narrows on `status = 'published'`,
  `validFrom <= now`, `validTo >= now`, and the delivery type of the tab.

So there are five reasons, and only one is "draft":

| reason                     | where it comes from                   |
| -------------------------- | ------------------------------------- |
| draft                      | `status`                              |
| not yet within its window  | `validFrom`                           |
| past its window            | `validTo`                             |
| on the other catalogue tab | `deliveryType` — On Demand vs Weitere |
| genuinely visible          | none of the above                     |

## The change

A **Sichtbarkeit** column on the course list, saying which.

No API change was needed, which is the sharpest part of this: `status`,
`validFrom`, `validTo` and `deliveryType` are already on `AdminCourseSummary`,
already in the contract's `required` list, and already arriving in the browser.
The console had every fact and rendered none of them.

The rule is `courseAvailability` from `@ds/domain` — the same function
`catalog.service.ts` applies to what its SQL returns — not a re-derivation of
the three comparisons. Two implementations of "who can see this" is exactly the
§4 invariant 6 shape that produces a console disagreeing with the catalogue.

The delivery-type note is separate and deliberately so: it is not availability,
`courseAvailability` knows nothing about it, and a published in-window course on
the Weitere tab is not a defect — it is a course somebody was looking for in the
wrong place.

## Why the intro text was not enough

The screen already said _"Until it is published it is a draft and participants
cannot see it."_ A rule stated in a paragraph and applied to no row is §9.4: the
person is looking at the thing the rule decides, and the rule is somewhere else.
