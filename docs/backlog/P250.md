## P250-02 addendum — no integration test may reach a real EIV system

**Found while doing TEST-4.** The first run of the new HTTP test for the
console's EIV routes sent requests — a withdrawal among them — to
`https://backend.eiv-fobi.de`. Migration 0053 defaults
`platform_settings.eiv_endpoint` to `live`; `reset.ts` restores that default
for every file; and 0053's consent gate guards only the **worker**, not the
console routes (check, describe, reconcile, withdraw), which build their client
from the setting armed or not (`eiv-admin.controller.ts`, `baseUrl:
eivEnvironmentUrl(environment, installation.endpointUrl)`). EIV refused at
authentication because the credentials were the fixture's. Pinning `mock` in
that file fixed the instance; CLAUDE.md §11.11 asks for the class.

**The class fix.** `test/integration/support/no-real-eiv.ts`, first in
`setupFiles`, wraps the global `fetch` the EIV client uses
(`packages/eiv-client/src/client.ts:480`) and refuses any URL
`eivEndpointTier` classifies as `live` or `test`. Every other address
(`unknown`: the fake bucket, mock JWKS) passes through.

Verified: the full suite with the guard installed — `pnpm test:integration
--fresh`: 32 files, 780 tests passed, and the guard never fired, so no other
suite currently reaches a real register.
