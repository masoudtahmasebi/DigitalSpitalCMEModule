## P250-01 — staff scope, delivery email, EIV claim

**Review gate:** human (auth, certificates, eiv) · closes TEST-1, TEST-2, TEST-3

**Acceptance criteria**

- [ ] TEST-1: a customer_admin POSTs a narrower scope to a super_admin's id →
      403, `admin_user_roles` unchanged. Red when the existing-grants loop in
      `staff.service.ts:835` is removed.
- [ ] TEST-2: two learners in one tenant on one course; A PUTs then GETs the
      delivery email; B's `delivery_email` is unchanged and A never sees it.
      Red when the `userId` predicate at `completion.repository.ts:170` is
      removed. The comment at `:49` is corrected: the predicate is the defence,
      not RLS.
- [ ] TEST-3: one due row; three `claim_due_eiv_submissions` calls on separate
      connections inside open transactions via `Promise.all`; the id appears
      exactly once in the union. Same for `claim_due_certificate_deliveries`.
      Red against a copy of the function without `FOR UPDATE SKIP LOCKED`.

## P250-02 — EIV admin over HTTP; multipart uploads; the stall test

**Review gate:** human (eiv) · closes TEST-4, TEST-5, TEST-6

      tenant's admin are refused; the own admin's `POST …/eiv/check` body
