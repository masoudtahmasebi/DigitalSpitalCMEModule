## P244-01 — five explicit-only NestJS skills under `.claude/skills/`

### Context

The leaderboard ranks repositories by recent pushes, not by vetting. Most
entries have 0 stars, several are off-domain, and some handle credentials or
session histories. A skill runs with the same access as the session: DB scripts,
the deploy tooling, and the code that reports CME points to EIV. So nothing is
installed that has not been read.

### Decision

| Candidate                      | Outcome  | Why                                                                                   |
| ------------------------------ | -------- | ------------------------------------------------------------------------------------- |
| `amirtaherkhani/nestjs-skills` | 5 of 7   | Our API is NestJS 12. Markdown plus one read-only script, audited in full             |
| `victorrentea/human-review`    | rejected | 184 executables (~94k lines), a local server, video recording; not auditable in scope |
| everything else on the board   | rejected | off-domain, redundant with CLAUDE.md §11, or touches personal data/credentials (GDPR) |

Details, exclusions and the local change are in `.claude/skills/THIRD-PARTY.md`.

### Acceptance criteria

- [x] Only skills whose every file was read are vendored, pinned to a commit.
- [x] None loads itself: each carries `disable-model-invocation: true`.
- [x] No skill can push, open PRs, switch branches or reach the network.
- [x] MIT licence text kept beside the vendored files.
- [x] `pnpm lint` and `pnpm format` pass; vendored content is not reformatted.
      Both tools ignore `.claude/skills/nestjs-*/`: unignored, the vendored
      script fails ESLint (`no-unused-vars`, `no-control-regex`) and 24
      vendored markdown files fail Prettier.

### Out of scope

No `apps/` change. This is development tooling only and touches none of the
human-review areas (auth, assessment, eiv, certificates).

### Found on the way: `check:docs-commands` misread dot-directory paths

`.claude/skills/THIRD-PARTY.md` names its script by repository path, and the
check looked for `claude/skills/…`: the regex opened with `\b`, which falls
between the dot and the name. Any `.mjs` path under a dot directory was
resolved without its dot. Now a lookbehind; shown red with the path broken on
purpose and green with it restored. The vendored skill documents are excluded
from that check (`VENDORED`), as from Prettier and ESLint, because their paths
are relative to the skill's own directory.
