# P88 — a media manager, and a console that speaks English

**Status:** built and verified locally, 17.08.2026. P88-01 through P88-04 done.
**Raised by:** the client, 17.08.2026 — _"close all the gaps, a complete media
manager for video, image pdf and so on / fix all of the admin."_

---

## Where it started

The client asked whether the Mediathek and the translations were done. Both
answers were "the mechanism, yes; the thing, no" — and neither gap was visible
from inside the product, which is why neither had been reported.

|               | What existed                                  | What was missing                                                             |
| ------------- | --------------------------------------------- | ---------------------------------------------------------------------------- |
| **Mediathek** | schema, API, a picker                         | the picker was mounted in **one field of one form**, for `kind="video"` only |
| **English**   | `overlay`, a language switch, a partial table | **36 of 632 strings**                                                        |

Both are the same shape as CLAUDE.md §9.1: nothing was broken. The picker
worked, the switch worked, every screen rendered. A gap that degrades
gracefully is a gap nothing can go red about.

## P88-01 — a Mediathek screen — **done**

`#/mediathek`, under **Angebot** beside the courses whose files it holds.

The picker's own header argued that a screen you have to visit and copy a
reference out of _"is not reuse — it is the same remembering, with extra
steps."_ That is still true of reuse, and it is why the picker stays. It is not
true of anything else somebody does with files: renaming a batch a colleague
uploaded, writing the alt text that was skipped, finding out which recording is
taking four hundred megabytes, clearing out a cancelled course. None of those
happens inside a content form, and until this screen the only way to reach any
of them was to open a course, begin adding a video, and use the picker as a side
door. The controls existed and the place to use them did not — §9.8.

What it has: filter chips over every kind (derived from the same MIME first
token the API indexes on, so a chip labelled _Bilder_ selects exactly what
`kind=image` returns), a search over the loaded page, previews for video,
images, PDFs and audio, the storage total, and the two empty states told apart —
"nothing matches this filter" is a thing to undo, "you have not uploaded
anything" is a thing to explain.

### `usedByCount`, so removal is a decision rather than a 409

Every row carries how many contents point at the file, from **one grouped
query** rather than one per row. The remove button is disabled while anything
uses it and the count beside it says why. The API refuses either way — that is
the gate — but a control whose only possible outcome is an error is worse than
an absent one (§9.2), and "In 3 Inhalten verwendet" is what somebody needs in
order to go and unpick it.

### `POST /admin/media/{id}/view`

The screen is not inside a course, so `adminViewUpload` — which checks the key
against the course's prefix — has no slug to check against and answers nothing
for every stored reference. That was a screen of grey rectangles.

Authorised by the **asset row** instead, which is under FORCE ROW LEVEL
SECURITY. That is the tighter answer rather than the looser one: a file
belonging to another customer is not visible to name in the first place, where
the course route has to compare two prefixes and get both right. Audited as a
`read` in the same way — a second route that did not write the row would be a
hole in an append-only log.

### The defect found while refactoring

The picker saved a rename from the input's `onChange` — **one `PATCH` per
keystroke**, each answering with the server's row, which then replaced the value
under the cursor. A twenty-character title was twenty round trips racing the
typist.

Drafts are now local and written when the field is finished with (blur, or
Enter), and a field somebody only tabbed through costs nothing. Both are
asserted, and both were watched to go red.

## P88-02 — the library wherever a file is uploaded — **done**

"Aus Mediathek wählen" now sits beside every upload button: poster, subtitles
and material as well as video. Each field asks for the kind it could actually
accept, mirroring `ACCEPT`.

It needs no course slug — the reference is already stored and choosing one is
assigning a string — so it stays available while a course is still being
created, which is exactly when somebody most wants the file they used last time.

**Not included:** the certificate stamp and signature. Those go through
`adminSetCertificateAssets` as base64 on the course row rather than to object
storage, deliberately (they are per-course compliance artefacts). Bringing them
into the library is a separate decision, not a wiring gap.

## P88-03 — the console speaks English — **done**

All 632 strings, including the long hints — which are the ones that matter,
because a label can be guessed from its field and a paragraph explaining what a
setting does to enrolments already under way cannot.

**The accreditation vocabulary stays German**: Lernerfolgskontrolle,
Teilnahmebescheinigung, Punktemeldung, Anerkennungsbescheid, Ärztekammer, EFN,
VNR. These appear verbatim on the Bescheid and in the EIV-FOBI interface, and an
operator reconciling a screen against the paperwork needs the same token in
both. "Learning assessment" is a _translation_ of Lernerfolgskontrolle and is not
the name of the thing; inventing an English equivalent for a term on a legal
document is the guess §7 refuses. Everything that is a product noun is
translated — _Fortbildung_ becomes **course**.

`scripts/i18n-coverage.mjs` is in `pnpm verify`, not only CI. It fails below
95 %, and reports an English key with no German counterpart as the typo it is —
`overlay` would never read one, so it would sit translated and unreachable for
ever (§9.3). Watched to go red: it reports **5 %** against the previous table.

Three tests in `language.test.ts` drive the tables that actually ship rather than
two fixture objects (§9.7 — name the caller).

## P88-04 — a required check that had never made a decision — **done**

Every pull request this repository has ever opened failed on `Dependency
review`:

```
Dependency review is not supported on this repository.
```

Always the same reason, never about the code: the action needs GitHub's
Dependency graph switched on, and it is not. §9.2 at the pipeline level — a gate
that cannot pass is not a gate, and a permanently red check is worse than an
absent one because it teaches everybody to stop reading the red ones.

Made **advisory**, not deleted. The policy it would apply is already enforced on
every push by `Security audit`: `pnpm audit --prod --audit-level=moderate` fails
the build on the same severity floor. What the action adds over that is the
per-PR comment naming which dependency changed — useful, and not a gate.

**Open, for the repository owner:** enable Dependency graph under Settings →
Advanced Security and delete the `continue-on-error`. A workflow cannot switch
the setting on for itself, which is §9.9's corollary exactly — so the enforcing
check is the one that runs rather than the one that is documented.

## Acceptance criteria

- [x] The Mediathek is reachable from the navigation, with its own address.
- [x] It covers video, images, PDF and subtitle files, with a preview for each.
- [x] Files can be renamed, given alt text and removed from one place.
- [x] Removing says what it would cost before the button is pressed.
- [x] The library is offered beside every upload field, filtered to what that
      field accepts.
- [x] A rename costs one request, not one per keystroke.
- [x] The console renders in English end to end, with the accreditation
      vocabulary intact.
- [x] A check measures translation coverage and can go red.
- [x] `pnpm verify`, the integration suite and the browser suite are green.
- [x] No CI job is red for a reason that is not about the code.

## Not done

- **The stamp and signature are outside the library** — see P88-02.
- **Paging.** `GET /admin/media` takes a `limit` and the screen filters the
  loaded page locally. Honest at a customer's likely volume and stated as such
  in `MediaLibrary`; if a library outgrows it the fix is paging in the API
  rather than a cleverer filter on the client.
