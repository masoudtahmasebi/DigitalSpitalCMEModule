## P34-01 · Act 7: the Punktemeldung actually leaves — **done**

- **Estimate:** 3 h · **Review gate: human — eiv**

The journey suite walked an empty cluster all the way to a certificate and an
operator's CSV, and stopped at **`queued`**. It proved the platform _decides_ to
report. Everything between that decision and the Kammer was covered only by
`eiv-worker.integration.test.ts`, which inserts its fixture course with
`INSERT INTO courses (…, vnr_password_enc)` — SQL, directly, bypassing the
console.

That gap is precisely where a real installation fails, and this session found it
the expensive way: an environment was configured with `EIV_VNR_PASSWORD` in
`config.env`, where nothing reads it, because the password belongs to the
_course_. Under that configuration every completion is abandoned
`missing_vnr_password` — permanently, one row at a time, inside an 8-day
statutory window.

So act 7 walks the path an operator walks:

| Step                                            | What it pins down                                                      |
| ----------------------------------------------- | ---------------------------------------------------------------------- |
| Sweep with no password on the course            | abandoned `missing_vnr_password`, not retried forever                  |
| `PATCH /admin/courses/:slug` with `vnrPassword` | accepted, and absent from the response and the read-back               |
| Read `vnr_password_enc` as the superuser        | ciphertext — the plaintext appears nowhere in the bytes                |
| Requeue, then sweep                             | the mock Kammer receives EFN, both point flags, a German calendar date |
| Read the audit log                              | no EFN, no VNR password anywhere in it                                 |

### Two things this changed about the suite

**It runs with a real AES-GCM key.** Without `SECRETS_KMS_KEY`,
`createSecretCipher` falls back to `PlaintextSecretCipher` and the ciphertext
assertion would have been passing against a cipher that does not encrypt.
Invariant 7 is now actually exercised end to end: the console writes it, the
column holds ciphertext, the worker decrypts it to authenticate.

The key is `Buffer.alloc(32, "ds-journey-kms-key-not-a-secret")`, derived rather
than pasted — a 32-byte base64 blob in a test file is what P33-02 spent an hour
clearing out of the history. The first attempt was 33 bytes and
`AesGcmSecretCipher` refused to construct, which is its length check doing
exactly what its comment promises, reported as a native stack trace out of
Nest's initialisation.

**`attempt_count` is 1, not 2.** Being abandoned for a missing password does not
spend a retry — `abandon` defaults `attemptCount` to the row's current value,
and the unit test calls this "abandons rather than burning the budget". The
course was misconfigured; the Ärztekammer was never asked. So when an operator
fixes it, the submission still has its whole budget for the failures that are
actually EIV's. The assertion in this act says so, because getting it wrong is
how somebody later "fixes" the counter and quietly halves the retry budget.

## P34-02 · Seventeen copies of the same three lines — **done**

- **Estimate:** 1 h · **Review gate: none**

The audit for duplication, anti-patterns and security issues, honestly reported
— including the parts that came back clean.

### What was actually wrong

`requireEnv` was declared, character for character, in **seventeen** integration
suites. It is not interesting code, which is why it spread: three lines somebody
reasonably wrote rather than went looking for.

The cost is not the duplication. **Fifteen threw one message and two threw
another**, so "what happens when `DATABASE_URL` is missing" already had two
answers, and improving the message would have had to be done seventeen times to
be true anywhere. It now lives in `support/env.ts` and names the command that
sets all four — which is what somebody hitting it actually needs, and which none
of the seventeen said.

### What came back clean, and is worth recording as such

| Checked                                         | Result                               |
| ----------------------------------------------- | ------------------------------------ |
| Interpolated SQL in application code            | **none** — every query parameterised |
| `any` / `as any` in `apps/api/src`, `packages`  | **none** outside prose               |
| Empty `catch` blocks                            | **none**                             |
| Non-null assertions in source (excluding tests) | 4                                    |

A duplication audit that reports only what it found looks like a thorough audit
of a bad codebase. Saying which checks came back empty is what makes the finding
above meaningful.

### Named, and deliberately not done

**Nine suites define an identical `insert(sql, values)` helper**, and fifteen
build the same customer → department → project → course fixture by hand.

Extracting the helper means rewriting ~50 call sites across nine files whose
pools are named three different things; extracting the fixture means an
abstraction over fifteen setups that genuinely differ in which columns they
care about. Both are real duplication. Neither is worth a lossy abstraction or a
half-migration, and a partially-extracted helper is worse than either version of
the duplication — so it is written down here rather than half-done.
