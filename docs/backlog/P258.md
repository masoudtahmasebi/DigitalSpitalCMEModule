## P258-02 — the fullscreen control bar was grey on black

**Review gate:** none · learner presentation · found by Q1, Q3 and Q5

P256 made the whole player go fullscreen as `bg-black`, and `Controls` had no
surface of its own, so every control in `text-gray-700` sat on black. Inline
it had inherited the player's `bg-gray-100`. `Controls` now owns
`bg-gray-100`, which keeps every colour in it at the contrast it already had
inline.

Verified: the journey now computes the exit button's contrast against the
first painted background behind it — red at **2.04:1** before the fix
(`Expected: >= 3`), green after. The same block replaces P256's `screen − 120`
allowance with `video.height + bar.height ≥ screen − 1`, measured.

## P258-03 — one question for "is this player fullscreen"

**Review gate:** none · found by Q3 and Q4

The toggle asked `document.fullscreenElement`, the listener asked the player's
own root. With any other element fullscreen, the first press exited instead of
entering. Both now call `isFullscreen(element)`, which also replaces the
unchecked `getRootNode() as Document | ShadowRoot` cast with `instanceof`.

## P258-04 — shortcuts work with focus on the control bar

**Review gate:** none · found by Q3

The key handler sat on the frame, so in fullscreen — where Tab moves into the
bar — `f`, `k` and the arrows stopped working. It is now on the whole player;
Space and Enter on a button are left to that button.

Verified: `VideoPlayer.test.tsx` — "answers its shortcuts with focus on the
control bar" red with the handler moved back to the frame; "lets Space on a
button be that button" red with the guard removed. 53 passed.

## P258-05 — the catalogue hero no longer jumps 184 px

**Review gate:** none · regression from P255-01 · found by Q3

P255-01 chose the band's height from `branding.catalogHeroImageUrl`, and
branding loads after the first paint, starting as `{}`. A project with a
photograph painted at 256 px, then moved everything below by 440 − 256 = 184 px.
`useBrandingStatus` now says whether branding is known; the catalogue shows its
spinner until it is, bounded by `BRANDING_WAIT_MS` (1.5 s) so a hung fetch costs
the photograph and not the page. The header and logo are not held.

Verified: `catalog-hero.test.tsx` — band drawn before branding answered: red;
hung branding: red with the timer sabotaged; all three green. Widget: 469
passed. Full e2e: 41 passed.
