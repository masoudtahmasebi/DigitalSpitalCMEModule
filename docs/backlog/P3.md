# Epic P3 · Learning engine — 14 h

**Week 3.** Enrolment, gating, progress and the video rule. Every decision in this
epic is made server-side; the client renders the result and is never the source of
truth (`CLAUDE.md` §4).

**Demo at end of phase:** gated playback works; leaving and returning lands on the
exact chapter and second; the video gate refuses to complete below the configured
percentage.

---

### P3-01 · Enrolment

- **jira:** _(unassigned)_
- **Estimate:** 2 h · **Week:** 3 · **Depends on:** P2-06
- **Review gate:** none

**Context**
Enrolment binds a learner to a course and pins the compliance settings in force at
that moment, so that a later threshold change cannot retroactively invalidate work
already done (P2-02 acceptance criterion).

**Scope**

- Enrol, list own enrolments, resolve enrolment state.
- Snapshot `pass_threshold_percent`, `required_watch_percent` and CME metadata
  onto the enrolment at creation.
- Re-enrolment is idempotent.

**Acceptance criteria**

- [ ] Enrolling twice yields one enrolment
- [ ] Changing the course threshold afterwards does not change an existing
      enrolment's snapshot
- [ ] Enrolment in a course outside the learner's tenant is impossible
- [ ] Enrolment outside the course validity window is refused with a clear reason

### P3-02 · Progress recording and watched-segment ingestion

- **jira:** _(unassigned)_
- **Estimate:** 3 h · **Week:** 3 · **Depends on:** P3-01
- **Review gate:** human — assessment

**Context**
`CLAUDE.md` §4 invariant 5: watched percentage is the **union of watched
intervals**, never the maximum playback position. A max-position implementation
makes any gate trivially skippable by dragging the scrub bar, which would make
every CME point issued by this system indefensible.

**Scope**

- Ingest playback heartbeats as `[start, end]` intervals into
  `content_progress.watched_segments`.
- Server merges overlapping and adjacent intervals via
  `mergeWatchedSegments` in `packages/domain`; the client's arithmetic is never
  trusted.
- Reject implausible intervals: negative, reversed, beyond content duration, or
  advancing faster than wall-clock between heartbeats.
- Throttle write frequency; autosave without hammering the API.

**Acceptance criteria**

- [ ] Overlapping segments merge; watched % never exceeds 100
- [ ] Re-watching an already-watched interval does not increase the percentage
- [ ] A client posting `[0, duration]` in one call is rejected as implausible
- [ ] A client-supplied percentage is ignored entirely — only intervals are
      accepted
- [ ] Segment storage stays bounded for a long video watched in many sessions

### P3-03 · Sequential gating

- **jira:** _(unassigned)_
- **Estimate:** 3 h · **Week:** 3 · **Depends on:** P3-02
- **Review gate:** human — assessment

**Context**
Gating is a compliance rule, not a UI affordance. It must hold against direct API
calls, not merely against a disabled button.

**Scope**

- `evaluateGate` in `packages/domain` returning `locked | available | completed`
  with a machine-readable reason, driven by the ordinals from P2-03.
- Enforced on every content-access endpoint, not only in the listing.

**Acceptance criteria**

- [ ] Requesting a locked chapter directly by ID is refused, with the reason
- [ ] Completing chapter N unlocks exactly N+1, not the whole module
- [ ] The reason code is specific enough for the widget to render the correct lock
      copy without inferring
- [ ] Gating is pure and unit-tested exhaustively with no database

### P3-04 · Progress rollup

- **jira:** _(unassigned)_
- **Estimate:** 2.5 h · **Week:** 3 · **Depends on:** P3-03
- **Review gate:** none

**Context**
`CLAUDE.md` §4 invariant 6: one rollup path. Learner and admin views read the same
function over the same repository method. Two implementations would eventually
disagree, and disagreeing numbers on a CME record is a compliance problem, not a
display bug.

**Scope**

- `rollupProgress` in `packages/domain`: content → chapter → module → course.
- One repository method feeding it, consumed by both the learner API and, later,
  the P9 participant list.
- Status, score and watched % exposed at every level.

**Acceptance criteria**

- [ ] Learner view and admin view return identical numbers for the same learner,
      asserted by a test that calls both
- [ ] A course with no content reports 0 %, not `NaN` or a division error
- [ ] Rollup is pure and unit-tested without a database
- [ ] Adding a content item to a course in progress recomputes correctly rather
      than stranding the learner above 100 %

### P3-05 · Resume

- **jira:** _(unassigned)_
- **Estimate:** 1.5 h · **Week:** 3 · **Depends on:** P3-04
- **Review gate:** none

**Context**
The demo criterion is exact: leaving and returning lands on the exact chapter and
second.

**Scope**

- Persist last position per content item and last content per enrolment.
- Resume endpoint returning the chapter and offset to restore.

**Acceptance criteria**

- [ ] Returning after closing the browser resumes at the same chapter and second
- [ ] Resume across two devices returns the most recent position, deterministically
- [ ] Resume never points at content that gating has since locked

### P3-06 · Video gate enforcement and anti-skip

- **jira:** _(unassigned)_
- **Estimate:** 2 h · **Week:** 3 · **Depends on:** P3-05
- **Review gate:** human — assessment

**Context**
The configurable rule from roadmap §2, enforced. MEDICE ships at 100 %, which
means the gate has no tolerance to hide behind — the merge logic in P3-02 must be
exact.

**Scope**

- Content completes only when `watchedPercent ≥ required_watch_percent` from the
  enrolment snapshot.
- Forward seek beyond `maxWatched + tolerance` rejected server-side.
- The gate reports the shortfall so the widget can tell the learner what remains.

**Acceptance criteria**

- [ ] At `required_watch_percent = 100`, a video with any unwatched interval does
      not complete
- [ ] At `required_watch_percent = 80`, 80 % of distinct content completes and
      79 % does not
- [ ] A forward seek past the tolerance is rejected and recorded
- [ ] The rule is read from the enrolment snapshot, not the live course record
- [ ] Boundary cases — exactly at threshold, exactly one second short — are
      unit-tested in `packages/domain`
