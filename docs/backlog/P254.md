## P254-01 — the default branch is `main`

**Review gate:** none · a repository setting, changed by the owner

Changed by the repository owner on 15.10.2026; confirmed by the repository API
answering `"default_branch": "main"`.

What it changes, read from the workflows rather than assumed:

- Scheduled CI now checks out `main`.
- `deploy.yml` is a `workflow_run` workflow, so every deploy until now ran the
  **default branch's** copy of `deploy.yml`, from 17.09. The next deploy is the
  first to run `main`'s. Not compared line by line — watch that run.
- The production guard does **not** change: `DEPLOY_BRANCH` is the literal
  `main` (P175-01) and `ds_release_ref_allowed` judges a `workflow_run` by
  `workflow_run.head_branch`, never by the setting.

The comments that described the old setting in the present tense —
`deploy.yml` (guard, journey checkout), CLAUDE.md §9.9b, P175 — now say it in
the past tense, and §9.9b gains the scheduled-run check.

### Noticed, not changed

`deploy.yml`'s _Fetch the deploy guards_ step checks out with no `ref`, so the
guard script comes from the tip of the default branch rather than from the
commit being deployed — the shape P240-01 removed from the journey job. With
the default now `main` the two differ only when `main` moves during a deploy.
It is the production guard, so it is not changed in passing; raise it as its
own ticket if wanted.

## P254-02 — CI can be run by hand

**Review gate:** none · CI trigger only

`ci.yml` had `push`, `pull_request` and `schedule`. A red scheduled run could
not be shown green on `main` short of a push: re-running it re-runs the same
commit. `workflow_dispatch` added.

A manual run on `main` that passes triggered Deploy exactly as a push to `main`
did — and so, once the default branch was `main`, did the weekly scheduled run
(19.10.2026: CI 10:39, Deploy 10:42:58, an unchanged commit). P258-08 limits
CI-triggered deploys to CI started by a push.
