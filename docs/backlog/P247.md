## P247-01 — participant reset sends a link; disable is per membership

**Review gate:** human (auth) · closes SEC-1

**Context**

A merge copies every membership and every identity onto one person
(`db/migrations/0033_participant_merge.sql:171`, `:173`). Every local identity
has the realm `ds:local` (`apps/api/src/auth/local-identity-provider.ts:76`),
so a merged person can hold two local credentials. Both the console's reset
(`participant.repository.ts:131`, `credentialIdFor`) and sign-in
(`participant-auth.repository.ts:128`, `findParticipant`) pick one with an
unordered `LIMIT 1`. Customer A's admin passes `isMember` for a person who also
belongs to customer B, and `resetPassword` returns `{ temporaryPassword }`; when
both queries pick the same credential, A's admin can sign in as the physician at
B. Disable sets `learner_credentials.disabled_at`, so A can lock them out at B.

Verified: the lines above, read on `0208b64`. Not reproduced against a
database. The comment in `participant-auth.service.ts` ("only the one for the
named project is touched") is false for sign-in.

Rejected: super-admin-only reset (takes a support task from customers);
refusing shared people (the client chose per-customer disable).

**Scope**

- `POST /admin/participants/:userId/reset-password` no longer sets or returns a
  password. It sends the person the existing P40 reset link
  (`beginPasswordReset`), using the caller's customer's local project; it
  answers 202 with no body. Contract and SDK change first.
- Disable moves to the membership: `user_customers.disabled_at` (and
  `disabled_by`), migration with backfill from `learner_credentials.disabled_at`
  onto every membership of that person. Sign-in and reset at customer B ignore
  a block set at A. `learner_credentials.disabled_at` is no longer read.
- `merge_participants` keeps exactly one local credential — the most recently
  used — and records which it dropped in the merge audit row.
- Console: the reset control says a link was emailed to the address on file
  and what to do if it does not arrive; nothing shows a password. Copy in the
  locale file. The disable control says it applies to this customer only.
- The false comment is corrected.

**Acceptance criteria**

- [ ] An integration case merges a person across customers A and B; A's admin
      calls reset-password; the response carries no password field and the
      person's credential hash is unchanged. Red on `0208b64`.
- [ ] A reset link is mailed only when the caller's project is `local` and can
      send; otherwise the answer is the same 202 and no token is minted (§9.5).
- [ ] A's admin disables the merged person; sign-in at B still succeeds and
      sign-in at A is refused.
- [ ] After a merge of two people with local credentials, exactly one
      credential remains; sign-in with the dropped password is refused.
- [ ] `pnpm check:roles` and the console screen agree: no control offers a
      password.

**Not in scope**

Federated (Keycloak) participants — their passwords are not ours (unchanged).

## P247-02 — media and SMTP hosts cannot point inside the network

**Review gate:** human (certificates: SMTP delivers them) · closes SEC-2

**Context**

`authoring.dto.ts:327` accepts any media URL; `media-check.service.ts:102`
fetches it with redirects followed and returns the status, an oracle into the
internal network. `projects.smtp_host` is the same class.

**Scope**

- Media URLs: `https:` only, on write.
- One outbound-address guard used by the media check and SMTP: resolve the
  host, refuse loopback, private, link-local, CGNAT and unspecified addresses,
  and names that resolve to them; no redirect following in the media check.
- The refusal names the field, never the value (§9.5).

**Acceptance criteria**

- [ ] Unit: `http://127.0.0.1:5432/` and `https://169.254.169.254/` are
      refused with no fetch made (fetch counter = 0).
- [ ] Unit: a redirect from a public URL to a private one is not followed.
- [ ] Integration: saving an `http:` media URL answers 400 naming `url`.

## P247-03 — one JWKS fetch per lifetime; staff sign-in throttled per IP

**Review gate:** human (auth) · closes SEC-3, SEC-4

**Scope**

- `jwks.provider.ts`: refresh the snapshot only when missing or older than
  `JWKS_CACHE_TTL_SEC`; one in-flight refresh per issuer. Also settles the
  "revoked key" needs-verification item: a `kid` absent from a fresh fetch is
  not served from the snapshot.
- `@RateLimit("staffLogin")`, keyed by client IP, on staff `login` and
  `totp/verify`, alongside the existing per-account lockout.

**Acceptance criteria**

- [ ] Unit: ten verifications within the TTL make at most one JWKS fetch
      (counter). Red on `0208b64`.
- [ ] Integration: the n+1th staff login from one IP inside the window answers
      429 with a problem document; another IP is unaffected.
