# Epic P5 · Learner frontend widget — 28 h

**Weeks 1 (2 h), 2 (1 h), 3 (10 h), 4 (10 h), 5 (5 h).** React + Tailwind built to
a Shadow-DOM custom element `<ds-lms>` embedded in MEDICE's WordPress site.

> **Budget note.** Roadmap §8 budgets 28 h; §9's weekly breakdown sums to 31 h.
> This backlog uses **28 h** per the recommendation in `docs/roadmap.md` §14, with
> the 3 h returned to P2 and the reduction taken from polish surface on the course
> list and detail screens — not from the responsive/a11y floor, which is
> non-negotiable per roadmap §1.

The widget renders decisions; it never makes them. Watch percentage, gating,
scoring and completion all come from the API (`CLAUDE.md` §4 invariant 1).

---

### P5-01 · Widget build pipeline

- **jira:** _(unassigned)_
- **Estimate:** 2 h · **Week:** 1 · **Depends on:** P0-02
- **Review gate:** none

**Context**
Roadmap §11 lists widget styling clashing with the MEDICE theme as a live risk.
Shadow DOM is the mitigation, and it has to be in place from the first line of UI
code — retrofitting style isolation later means re-testing every screen.

**Scope**

- Vite build producing a single self-registering `<ds-lms>` custom element.
- Tailwind compiled **into** the shadow root, not the document.
- `demo.html` harness for local development against the mock/dev API.

**Acceptance criteria**

- [ ] The build emits one JS bundle that registers `<ds-lms>` on load
- [ ] Component styles render inside a shadow root
- [ ] Host page CSS — including an aggressive `* { }` reset — does not alter the
      widget
- [ ] The widget's styles do not leak into the host page
- [ ] Fonts and assets resolve correctly when served from a different origin than
      the host page

### P5-02 · SDK wiring, token acquisition and refresh

- **jira:** _(unassigned)_
- **Estimate:** 1 h · **Week:** 2 · **Depends on:** P5-01, P2-06
- **Review gate:** human — auth
- **Implements:** ADR-0003

**Context**
The token is fetched at runtime from the WordPress endpoint, never read from page
HTML (ADR-0003). Refresh happens before expiry so a learner is not interrupted
mid-video.

**Scope**

- Consume `packages/sdk`; attach the bearer token.
- Fetch the token from the WP REST endpoint with its nonce; refresh pre-emptively.
- Three explicit states: logged out, token expired, refresh failed.

**Acceptance criteria**

- [ ] The token is never written into the DOM, `localStorage` or a query string
- [ ] A token expiring mid-video is refreshed without interrupting playback or
      losing progress
- [ ] A failed refresh surfaces a recoverable state, not a blank widget
- [ ] A 401 from the API triggers exactly one refresh attempt, not a loop

### P5-03 · Player shell — video and module/chapter navigation

- **jira:** _(unassigned)_
- **Estimate:** 5 h · **Week:** 3 · **Depends on:** P5-02, P3-06
- **Review gate:** none

**Context**
The core learner screen. Lock states shown here come from the server's gating
reason codes (P3-03) — the widget renders them, it does not compute them.

**Scope**

- Video player with heartbeat reporting of watched intervals to P3-02.
- Module/chapter sidebar with per-item status and lock states.
- Forward-seek restriction reflecting the server's rejection.

**Acceptance criteria**

- [ ] Heartbeats post intervals, never a computed percentage
- [ ] Lock states render from the server's reason codes with the correct German
      copy per state
- [ ] A locked chapter cannot be opened by URL manipulation — the API refuses and
      the widget handles it gracefully
- [ ] Progress survives a mid-video network interruption and resumes reporting
- [ ] Keyboard navigation reaches every control; the player is operable without a
      mouse

**Video captions: the engineering half is done** (best-practices audit, B-01).

This entry used to say the gap was "not an engineering problem" because nothing
in the schema could carry a caption file. That was true while courses were
seeded by hand; it stopped being true when P9-04 shipped authoring, and the
warning sat there for a while after the reason for it had expired.

Built now: `contents.captions_url` (migration 0015), a field on the content form
that says what is owed and why, the URL signed with the same lifetime as the
video, and a `<track kind="captions" default>` in the player. An author supplies
a WebVTT URL and a learner's player offers the track — asserted end to end in
`authoring.integration.test.ts`.

**What remains is the content obligation**, and it is on the Veranstalter: the
`.vtt` files themselves. The console shows a warning on any video without one
rather than refusing the save, because a slide-only recording with no speech
legitimately has none and neither the form nor the server can tell it from a
lecture.

Still worth raising with MEDICE alongside the other content assets. WCAG 1.2.2
is Level A and EN 301 549 is the reference standard in Germany — a CME course a
deaf physician cannot take is a discrimination exposure, not only an
accessibility score. The difference is that the platform is now ready for the
files the moment they exist.

### P5-05 · Course list with filters

- **jira:** _(unassigned)_
- **Estimate:** 3 h · **Week:** 4 · **Depends on:** P5-04, P2-05
- **Review gate:** none

**Scope**

- Course list with `Thema` and `Altersgruppe` filters and facet counts.
- Per-course status and progress summary from the rollup.
- Empty, loading and error states.

**Acceptance criteria**

- [x] Filters reflect server-side facets; no client-side filtering of a partial
      list
- [x] Status per course matches the rollup exactly — **satisfied by not
      showing a percentage.** `CourseSummary.enrolment` carries whether the
      caller is enrolled and whether it is finished; both are stored columns.
      A percentage per card would mean a `rollupProgress` over the whole tree
      for every row, and the cheap approximation that invites would be a second
      answer to "how far has this person got" — the thing CLAUDE.md §4
      invariant 6 exists to prevent. The percentage is on the detail screen,
      from the one rollup path.
- [x] Empty and error states render within the shadow root with correct copy
- [x] Filter controls are keyboard operable and labelled for screen readers —
      native `<select>` with a `<label for>`, and each chip is a button whose
      accessible name says what removing it does

### P5-06 · Course detail with four tabs

- **jira:** _(unassigned)_
- **Estimate:** 5 h · **Week:** 4 · **Depends on:** P5-05
- **Review gate:** none

**Context**
The Zertifizierung tab is where the 80 %/100 % copy contradiction lives (roadmap
§11). The tab must render the course's **actual** `required_watch_percent`, not a
hardcoded number — that is what makes the contradiction impossible to ship.

**Scope**

- Tabs: Übersicht, Experten/Referenten, Zertifizierung, Mediathek.
- Mediathek with lock states per item.
- Zertifizierung showing CME points, VNR, validity and the real configured watch
  and pass percentages.

**Acceptance criteria**

- [x] No percentage anywhere in the UI is hardcoded — all read from the course
- [x] Mediathek lock states match server gating exactly — a locked item has no
      `fileUrl` at all, so the padlock is the absence of the URL rather than a
      rendering decision
- [x] Tabs are keyboard navigable with correct ARIA roles and focus management
- [ ] ~~Deep-linking to a tab works and is restorable~~ — **deliberately not
      done.** The widget holds navigation in component state and never touches
      the URL: it lives inside a WordPress page whose history belongs to the
      host theme, and pushing entries there breaks the browser Back button in a
      way a learner experiences as the page vanishing (see `App.tsx`). Revisit
      only if a host page asks for it, and then via an explicit opt-in
      attribute rather than by default.

### P5-11 · Layout alignment pass — the player screen and the §4.2 corrections

- **jira:** _(unassigned)_
- **Estimate:** 6 h · **Week:** 5 · **Depends on:** P5-03, P5-04, P5-06
- **Review gate:** none

**Context**
Raised by the plan owner: _"the source of truth is the layout, please develop
against the given layout."_ The widget had been built against the requirements
prose, which is downstream of the approved screens and is not a substitute for
them. Auditing the two against each other turned up one silent defect and three
screens' worth of missing chrome.

The defect is the reason this is a ticket rather than a polish pass. The
Übersicht progress ring's **arc** was fed `progress.percent` — content-weighted —
while its **caption** was built from `moduleCompletion`. Both numbers are the
server's and both are correct; they are answers to different questions, and the
ring drew one while saying the other. Nothing is visibly broken on a course where
they happen to agree, which is every course at 0 % and at 100 %.

**Scope**

- Feed the ring from `moduleCompletion`, arc and caption from the same pair.
- §4.2 sticky metadata bar; the _Ihr Fortschritt_ card on all four tabs.
- §4.2 Mediathek: locked groups blurred behind a padlock, layout copy.
- §4.3 player: progress panel, **Modul Übersicht** sidebar with per-item state
  icons, **Fortbildung pausieren** / **Zurück zur Übersicht**, and the three
  content tabs.
- `clockTime` in `@ds/domain` for the `14:35 / 25:45` reading.

**Acceptance criteria**

- [x] The ring's arc and its caption are drawn from the same two numbers, and a
      test fails if the arc is fed a percentage again
- [x] The metadata bar stays visible while the Übersicht tab scrolls
- [x] The progress card appears on all four tabs and not over the player
- [x] The player shows `Modul N von M` counted from the tree, the timeline
      against the authored length, and the autosave sentence
- [x] The sidebar lists every module including locked ones; locked contents are
      rendered and not openable
- [x] Every sidebar state has an accessible name — the glyph is the only cue
- [x] Locked tabs render the padlock and the reason and offer no way through
- [x] Mediathek locked groups are blurred, padlocked, and hidden from assistive
      technology rather than read out as an unreadable smear
- [x] No compliance figure is computed in the widget; every gate rendered is a
      server field

**Deliberately not met**

- **"The autosave indicator shows saved only after the server confirms"**
  (P5-04). The layout specifies a _static sentence_ — _"Ihr Fortschritt wird
  automatisch gespeichert"_ — not a state indicator, and the layout is the
  source of truth for this pass. The sentence is made true rather than
  decorative: pausing now flushes the watched intervals, as do the timer, the
  end of the video, and the page being hidden. If a live saved/saving indicator
  is wanted, it is a layout change and a separate ticket.
- **Zur Teilprüfung**, omitted — out of scope per
  `docs/requirements/medice-adhs.md` §6.1. See §4a for the full deviation list.

**Open**

- **S16** — what `63% absolviert` measures. Shipped as
  `63 % der Fortbildung absolviert` so the number states its own referent; the
  wording is provisional until MEDICE confirm the intended quantity.
