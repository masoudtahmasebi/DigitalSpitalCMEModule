# P125 — The Fortbildungsnummer is the VNR, and the platform held two of them

**Status:** P125-01 built. P125-02 (drop the column) deliberately deferred one
release.

---

## The answer

> _"Fortbildungsnummer is the same as vnr."_ — the client, 27.08.2026

That closes **S31**, open since 12.08 (P62-02). The show-stopper always said one
sentence from MEDICE _or_ the ÄKWL would settle it, so it never needed the
Kammer — and Question 4 of the drafted ÄKWL letter comes out.

## What was wrong, and why it was invisible

`courses.fortbildungsnummer` has existed since `0001_init`. It was editable in
the console, rendered one line on the learner's Zertifizierung tab, and was read
by nothing else — not the Teilnahmebescheinigung, which carries the VNR as text
and two barcodes, and not the Punktemeldung, which sends the VNR.

So the platform had **two writable fields for one number**. An operator could
put one value in `fortbildungsnummer` and another in `vnr`, after which the
screen a physician reads shows one number and the report filed at the
Ärztekammer carries the other, with nothing anywhere to say they disagreed.

It survived nine QA sections because it is NULL on every seeded course and the
tab omits the line entirely when it is null. An absent value renders as an
absence rather than an error (§9.4's inverse: nothing to notice, so nobody
noticed).

## P125-01 — one number, one field

The label is the layout's and stays (§5 — the layout copy is authoritative, and
_Fortbildungsnummer_ is what page 04 draws). The **value** is now `vnr`, which is
the number actually reported.

Removed from `contracts/openapi.yaml` first, then the SDK regenerated from it —
the contract is the source and `check:sdk` enforces that. Then the API's DTOs,
repository projections and admin patch; then the console's field, so a second
number cannot be entered at all (§9.2: a control whose value the system ignores
is worse than no control); then the two locale entries the console no longer
renders, which `check:copy` would otherwise have failed on.

The contract's own description of the field was wrong in a way worth recording:
it called the VNR "the EIV credential [which] never leaves the server", two
lines below the `vnr` property in the same response schema. The VNR is printed
on the certificate and encoded in two barcodes; it is the VNR _password_ that is
secret.

Two tests, both watched to go red: the tab renders the VNR under the layout's
label, and it omits the line when a course has no VNR.

## P125-02 — the column outlives the code on purpose

`fortbildungsnummer` stays in the database, unread, for one release.

A deploy runs migrations **before** it swaps containers. Dropping the column in
the same change would give the still-running old API a window in which it selects
a column that no longer exists — §9.9's "a schema older than the code that writes
to it", with the arrow reversed and the same class of error message.

The drop is its own migration and asserts first that no row holds a
`fortbildungsnummer` differing from its `vnr`. If one does, that is a data fault
to surface rather than discard: it is exactly the disagreement this phase exists
to make impossible.

## Not in scope, and flagged rather than assumed

The client also said the course will be extended and that neither format nor
content changes. That is recorded against **S14**. It makes the letter's premise
accurate and makes the extension question more urgent — it does **not** decide
that the platform change needs no notification to the ÄKWL. The Bescheid requires
changes "jeglicher Art" to be notified and names _Umwandlung in ein Online-Format_
as an example; whether a delivery swap with identical content counts is the
Kammer's determination. Concluding otherwise from here is the invented rule §7
refuses.
