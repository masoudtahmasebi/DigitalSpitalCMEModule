## P246-01 — brainstorming starts itself; the API audit runs weekly

**Review gate:** none — development tooling and a read-only routine; no
`apps/` change.

**Context**

P245-01 installed `brainstorming` and `writing-plans` as explicit-only, so they
help only when somebody remembers to type them, which is exactly when they are
least needed. The reason for explicit-only no longer holds for these two: they
are our own adaptation and enforce CLAUDE.md rather than compete with it. What
must still not happen is upstream's behaviour — firing on everything — so the
trigger is narrow.

The NestJS skills (P244-01) stay explicit-only: they are vendored general
advice.

The audit found 18 findings on 05.10.2026. A one-off report decays; a weekly
re-run against a written baseline says what is new and what was fixed.

**Scope**

- `brainstorming` loads itself for a request to build, add, change or remove
  behaviour with no approved ticket; not for questions, reviews, audits or work
  a ticket covers. `writing-plans` loads itself after a ticket is approved.
- `docs/code-audit-api.md`: the 05.10.2026 findings as the baseline.
- A weekly routine (claude.ai Routines, not CI): Monday 06:57 Europe/Berlin, a
  fresh session runs the audit on `main` and reports new and resolved findings
  against the baseline. It changes nothing and pushes nothing.

**Acceptance criteria**

- [x] Both skills listed as model-invocable. Verified: after the frontmatter
      change the session's skill list showed `brainstorming` and
      `writing-plans` with the new descriptions.
- [x] The NestJS skills still carry `disable-model-invocation: true`.
- [x] The baseline names every finding with file and line.
- [x] The routine exists, is read-only by instruction, and stores no
      connectors.
- [x] `pnpm format`, `pnpm lint`, `pnpm check:backlog`, `pnpm check:static`
      pass.

**Not in scope**

Fixing any finding. Each becomes its own ticket, through `brainstorming`.
