### `View` was a second copy of `Route`

`App.tsx` wrote out a fourteen-member union that `routes.ts` also wrote out —
and `routes.ts`'s own header said _"Mirrors the `CourseTab` union in
`App.tsx`"_. Two homes for one value (§9.10b): adding a screen meant editing
both, and nothing would have failed if you edited one. `View` is now
`type View = Route`.

### What the extraction is actually for

Three questions were previously only answerable by rendering a signed-in
console against a mocked API:

- does a `course_editor` get a **Teilnahme** heading with nothing under it?
- does exactly one sidebar row carry `aria-current="page"`?
- what does the top bar say when nobody is signed in?

They are pure questions about a table and two components. `App.test.tsx` remains
the test that proves the console **calls** any of it — §9.7, name the caller —
and it is unchanged and still green, which is the evidence that behaviour did
not move.

### `check:roles` parses that table, and it failed closed

`scripts/role-matrix.mjs` reads the `NAV` literal out of a source file, so
moving the file broke it — **loudly**:

```
role-matrix: the navigation and this script's screen list disagree.
  navigation:
  this script: branding, certificates, copy, courses, …
```

It is repointed, reports `4 roles × 13 screens` again, and was re-sabotaged
(removing the `customer` capability) to confirm it still names the three roles
that would be offered a screen the API refuses. That it failed rather than
sweeping zero screens and reporting a pass is the property worth keeping, and
the comment now says so.

## P223-02 — the language switch was named "EN" to a screen reader

Found by asserting, in the new `TopBar` test, that the switch's accessible name
says where it leads. It did not. The call site had been passing

```tsx
<Button aria-label={de.language.switchTo(…)}>EN</Button>
```

since **P86-01**, and `Button` declares `ariaLabel` — camelCase. A hyphenated
JSX attribute is **never** checked against a component's props, because it
cannot be a JavaScript identifier. So React dropped it, TypeScript said nothing,
and the button's accessible name was the two letters "EN" — to the one person
who most needs that control, being the one who cannot read the current language
(§9.4).

**P68-02 already found this class** — three fields in the video sources editor
announcing _"Eingabefeld, leer"_ — and fixed `TextInput` and `Select`, whose
declarations carry a long comment explaining the trap. `Button` kept the
camelCase spelling. That is §9.11 exactly: the fix went where the report was.

So: one spelling across the three primitives, `Button` and `ConfirmButton`
migrated along with their six call sites.

### The class, closed by a check rather than a third fix

`node scripts/aria-props.mjs`, in `pnpm verify`. For every
`<Capitalised … aria-x=…>` in the front-end sources it resolves that component's
own props declaration and requires the exact key. Sabotaged, it says:

```
aria-props: an aria attribute is being silently dropped

  apps/admin/src/components/shell/TopBar.tsx:63: <Button aria-label=…> —
    Button does not declare "aria-label", so React drops it.
  …and the three other call sites
```

**Two defects in the checker itself, both found by breaking the thing it checks
rather than by reading it:**

1. **It was matching my own doc comment.** The first version searched the raw
   props block for `"aria-label"`, and the paragraph on `Button` explaining the
   decision contains that string — so the declaration could be renamed to
   anything and the check stayed green. That is the `check-deadlines` defect
   from CLAUDE.md §11 reproduced exactly: _"It was matching prose in doc
   comments."_ Comments are stripped now and the match is on the declaration
   shape, not on a mention.
2. **`Button` is declared in two apps.** A map keyed by bare name let the last
   file scanned win. It happened to be the right one, by alphabet. Keyed by
   app and name now.

It also prints what it could **not** resolve, and exits non-zero if it resolved
nothing at all — because a checker that silently covers less than it claims is
§9.1's second form, and this script exists because of a defect of that shape.
