# P80 — the two small things in the content form

Both reported in the same message as the media-library request, and both small
enough to ship ahead of it.

---

## P80-01 · the poster fills itself from the video

> _"the preview picture should be automatically as the first second of the video
> if no image is selected."_

Without a poster the player shows a black rectangle until the first frame
decodes — on a course card and on the player's idle state that is
indistinguishable from a video that failed to load. So every author _should_
set one, and asking each of them to export a still from their own recording is
asking for work the browser does in a second.

`capturePosterFrame` loads the video, seeks, draws one frame to a canvas and
hands back a JPEG `File` — which then goes through **the ordinary upload path**:
same presign, same key prefix, same storage audit row. A second upload path for
posters would be a second set of rules to keep in step.

**A second in, not frame zero.** Frame zero of a real recording is very often
black: an encoder's first keyframe on a fade-in, a title animation, a camera
still adjusting exposure. A black poster is no better than none. Clamped to the
midpoint for a video shorter than a second, which is what the client's own test
clips are.

**Only into an empty box.** It never replaces a poster an author chose, and the
ordinary upload field is untouched underneath.

**Every failure is silent and answers `undefined`.** A tainted canvas — the
bucket answering without the CORS headers this origin needs — is the expected
one, and a codec the browser cannot decode is the other. A poster is a
convenience and the field beside it still works, so a failure leaves the box
empty rather than interrupting an author with an error about something they did
not ask for. `attemptedRef` records the source it tried, so a failure happens
once rather than on every keystroke, and a timeout guarantees it settles rather
than holding a detached `<video>` and its buffer for the lifetime of the page.

### What the tests can and cannot hold

jsdom has no decoder and no canvas raster, so they do not assert that a real
frame comes out — the browser journey is where that would live. They assert what
is _logic_: where in the clip the still is taken, the short-video clamp, that
every failure path answers rather than throws, and that it always settles.

Red-checked: capturing at zero fails three, letting the tainted canvas throw
fails a fourth.

## P80-02 · a new file is not a defect

> _"also when i upload a new video, i again see: `Die gespeicherte Länge (2140
Sekunden) stimmt nicht mit der Videodatei überein (7 Sekunden). Ist die
gespeicherte Länge größer als die Datei, konnten Teilnehmende diesen
Abschnitt nicht abschließen.`"_

The notice was right about the numbers and wrong about the situation. P76-03
wrote it for one case — a stored length that disagrees with the file **that was
already there**, which means that content really had been refusing to complete.
It fired for a second case it could not distinguish: the operator has just
uploaded a _different_ file, so of course the stored length describes the old
one. Nobody was ever blocked, and the message said they were, about a video no
learner has seen.

`openedWithSource` records the source the form opened with, so the two are now
told apart:

|                           |                                                               |
| ------------------------- | ------------------------------------------------------------- |
| same file, lengths differ | amber — this content was blocking learners, save to repair it |
| source changed here       | plain — „Neue Datei erkannt", the length followed it, save    |

### Acceptance criteria

- [x] An empty poster box fills itself from the video, once, per source
- [x] A poster the author chose is never replaced
- [x] Capture failure is silent and cannot loop
- [x] The mismatch notice only alarms about a file that was already there
- [x] Red-checked on both

## Deliberately not done

**Capturing a poster for a source the browser cannot decode.** The still comes
from the same media pipeline the learner's player uses; if it cannot decode the
file, neither can they, and that is `MediaCheck`'s subject rather than this
field's.
