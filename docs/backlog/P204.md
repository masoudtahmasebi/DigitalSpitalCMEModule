# P204 — Three layout deviations the client named

**Raised by:** the client, 07.09.2026 — _"there is a not needed `mb-4` and
`space-y-6 py-4` which makes this different than the design. the tabs which are
not selected, should have a padding or margin bottom to match the design."_

---

## What changed

|                           |                                                                                                                                                                                                                                           |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `py-4` on the widget root | **removed.** The hero is meant to meet the page header; the padding put a band of the host page's background above it. `space-y-6` **stays** — that is the gap _between_ the logo, the hero and the content, which the drawing does have. |
| `mb-4` on `CourseHeader`  | **removed.** The parent's `space-y-6` already sets the gap under that block, and the two stacked.                                                                                                                                         |
| inactive tabs             | `sm:mb-1.5`, so they stand _off_ the panel while the selected one merges into it.                                                                                                                                                         |

## The tab row, and why the margin needed a second change

The selected tab has `relative -mb-px`: it overlaps the panel by a pixel so the
two read as one shape. The inactive tabs sat on the same baseline, so the row
read as four attached tabs with one painted white — "selected" was carried by
colour alone.

A bottom margin alone would not have moved them. Flex items stretch by default,
so a margin on a stretched item eats its height instead of lifting it — the tabs
would have got shorter. `sm:items-end` on the tablist is what makes the margin
mean what it looks like it means.

`sm:` only, on both: below that breakpoint the row is `flex-col`, where
`items-end` would right-align the stacked buttons.

## What I cannot verify

**That these now match the design.** I do not have the 01.09.2026 export, and
these are pixel judgements against a drawing. What is verified is that the
classes named are gone or changed as described, that 417 widget tests still
pass, and that the mobile layout is untouched by the tab change.

The three values removed were deliberate, and their reasoning is in P190-01's
own comments — I have taken the client's word that the design says otherwise,
because on layout it does (CLAUDE.md §5: the layout is authoritative). If any of
the three was load-bearing for a case the drawing does cover, it will show on the
next look and the reasoning to restore it is still in the file's history.
