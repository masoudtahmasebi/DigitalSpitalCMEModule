# P122 — The string that finds the failing request reached the payload and stopped

**Status:** built (`a468b07`), plus the test pack it exists to serve.

---

## P122-01 — the correlation id nobody could see

The API has minted a correlation id per failure and returned it on every error
response since observability landed. No client read it.

So the one string that locates a failing request in the server log travelled all
the way to the browser and was discarded one layer short of a person. Somebody
reporting "it did not work" could not hand over the thing that would find it,
because nothing had ever shown it to them.

This is §9.3 with the layers reversed. There, a rule written and never called;
here, a value produced, transmitted, and never rendered.

**Built:** `correlationId` documented on `ProblemDetails`, exposed as
`problemCorrelationId()`, appended by both `describeError`s — `(Referenz: …)` in
the console, `de.error.reference(id)` in the widget's locale file.

**Deliberately not appended** to two paths: an expired session, and a course
that does not exist. Those are ordinary outcomes a person can act on, and a
reference number attached to every one of them trains everybody to ignore the
one place it matters. Watched to go red in both directions — one test red when
the append is removed, two red when the guard is.

Safe to render: a random UUID identifying a log line, never a person (§9.5).

## P122-02 — the test pack in Jira

Seventeen tickets in project **DEP**, assigned to Amruth: DEP-5 as the hub and
DEP-6 … DEP-21 as the pack, mapped to `docs/testing/` in that directory's
README. The pack is weighted at the widget **inside MEDICE's WordPress page**,
because that is what a physician sees; the admin console appears once, at the
end, to check that what the journey produced was recorded correctly.

Three things the Jira copy carries that the files did not:

- **A reporting format** (DEP-5) built around the four facts that turn a report
  into a fix: the build and commit, the exact URL, the `(Referenz: …)` id from
  P122-01, and expected-vs-actual in that order. The first of those is §9.9 made
  into a form field — without it, "the feature is missing" and "the feature is
  not on the server you are looking at" are the same report.
- **An "Expected refusals" section on every ticket**, naming the guards that
  look like defects: a refused forward seek, a locked exam, a DocCheck visitor
  left signed out, the certificate's empty Anschrift line. Each has been
  reported as a bug before. A guard reported as a defect costs the same round
  trip as a defect never reported.
- **The gate from P121** as the pack's first instruction.

## What this changed in the rules

`CLAUDE.md` §10 said DEP was not yet populated, and described what to do when it
was: move commits to the `DEP-123` form. That is now a trap rather than an
instruction — a DEP key today names a _test ticket_, so `DEP-13: …` on a commit
would point at "Lernerfolgskontrolle" instead of a work order. §10 now says so,
and says the backlog migration has not been done.
