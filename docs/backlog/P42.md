# P42 · The address bar, and a tenant that was never seeded

> in the admin panel, with page changes, the route does not change
>
> i have a medice client, and when i go to
> `https://fortbildung.digitalspital.com/medice` it says "Diesen Bereich gibt es
> nicht" … and `https://api.digitalspital.com/tenants/medice` says
> `{"kind":"unknown"}`
>
> still no forget password in `https://verwaltung.digitalspital.com/` login

Three reports in one message, and they are three different kinds of thing —
which is itself the useful observation. One is a defect, one is an installation
that does not contain what the repository contains, and one is a feature that is
built and not deployed. Telling them apart is most of the work; the fixes are
small.

---

## P42-01 · The console's screen belongs in the URL — **done**

- **Estimate:** 3 h · **Review gate: none**

`view` was React state and nothing else, so every screen in the console lived at
one URL. Three things follow, and an operator meets all of them within a minute:

- **Back leaves the console.** As far as the browser is concerned nothing has
  happened since the page loaded, so the back button goes wherever they were
  before — usually the login screen or another site entirely.
- **Reload loses your place.** Somebody deep in a course's quiz editor who
  presses F5 lands on the course list.
- **Nothing is linkable.** "Look at this course" is a screenshot and directions,
  not a URL.

### The fragment, not the path

`#/fortbildungen/adhs-akademie-adult/quiz`. The console is a static bundle behind
a server that knows one route, so a deep _path_ would 404 on reload unless the
server were taught to rewrite — and reload working is the entire point.

### By hand, not a router

A closed union of ten screens with at most two parameters. A router would be a
dependency, a provider and a set of idioms in exchange for `encode`/`decode`,
which are forty lines and, being pure, are exhaustively testable in a way a
`<Route>` tree is not. `apps/admin/src/routes.ts`, `routes.test.ts`.

The segments are German — `#/fortbildungen`, `#/teilnehmende`, `#/sicherheit` —
because the console's copy is authoritative and German (CLAUDE.md §5), and an
operator sending a colleague a link should see the word they use for the thing.
The `kind` values stay English because they are code.

### The tests are in two files, deliberately

`routes.test.ts` covers `encode`/`decode` exhaustively — and **would have passed
on the broken console**, because the console never called them. So the wiring
gets its own tests in `App.test.tsx`: what the address bar says after a click,
what is drawn when the address bar says it first, and what `popstate` does. All
three were confirmed by breaking the wiring and watching them go red
(CLAUDE.md §9.1); the first two failed on `pushState` disabled, the third on the
mount-time `decode` removed.

### What it cost elsewhere, which is the part worth recording

`App.test.tsx` needed `afterEach(() => window.history.replaceState(null, "", "/"))`.
jsdom keeps one URL per file, so the first test that navigated left the next one
mounting on that screen — surfacing as _"Neue Fortbildung is not on the page"_,
which reads like a rendering bug and is not one. The same shape as the
`localStorage` reset two phases earlier: **state that outlives a test is a
failure attributed to the wrong code.**

## P42-02 · `/medice` was right, and unhelpful — **done**

- **Estimate:** 2 h · **Review gate: none**

Not a defect. `GET /tenants/medice` answered `{"kind":"unknown"}` because the
live database has no project slugged `medice` — the MEDICE seed has never been
run on that host. `packages/seed/src/medice-adhs.ts` creates both channels
correctly, and `deploy.sh` deliberately runs only `seed-ds-default --if-missing`,
because the other seeds rebuild a course's content tree unconditionally and that
deletes learner progress against it. So the seed is manual, by design:

```
./dsc seed medice
```

### Correct behaviour is not the same as usable behaviour

The portal cannot say more than "no such tenant". Naming the tenants that _do_
exist would hand anyone who visits a list of the platform's customers — an
oracle, CLAUDE.md §9.5 — so the portal's message is as good as it can safely
get, and it still leaves the operator with nothing to act on.

The place that can answer is the deploy, where the operator already is and is
already trusted. `deploy.sh` now closes by printing the tenant paths this
installation serves:

```
Tenant paths on the portal:
  https://fortbildung.digitalspital.com/ds
  https://fortbildung.digitalspital.com/dscustomer
```

and, when there are none, says so and names the command. **Local projects only**
— a Keycloak-bound project is reached through the customer's own site (MEDICE's
WordPress plugin), never by a portal path, so listing one would advertise a URL
that does not work, which is the failure this exists to stop.

A report, never a refusal: a deploy that succeeded must not report failure
because a `psql` could not run.

### What this does not fix

The seed still has to be run by a person. Making the deploy run it would mean a
deploy that rebuilds a content tree and deletes progress — strictly worse than a
missing tenant.

## P42-03 · "Still no forget password", and asking a process what it is — **done**

- **Estimate:** 1 h · **Review gate: none**

The feature is built. P40 landed on this branch, and the branch is not deployed.
No code defect — but two rounds went into establishing that, because **"the
feature is missing" and "the feature is not on the server you are looking at"
are indistinguishable from a browser.**

The general form: _a report about a running system is a report about a commit,
and the first question is which one._ The deploy log answers it once
(`Deployed <sha>`) and then scrolls away; nothing could be asked afterwards.

Now `ds_build_info{commit="…"} 1` on `/metrics`, and `DS_COMMIT` is passed into
the API container.

### Why `/metrics` and not `/health`

`/health` is public — a load balancer cannot present a bearer token — and a
version string on a public endpoint is a fingerprint telling anyone which
vulnerabilities to try. `/metrics` is `@Public()` in the same sense but is **not
routed from the edge** (`infra/deploy/Caddyfile`), so reaching it needs a place
inside the Docker network: an operator has one, the internet does not.

`_info`-gauge-at-1, the convention `node_exporter` and `prom-client` both use,
so it joins in a dashboard. It renders `commit="unknown"` rather than omitting
the series when unset — a missing series and one saying `unknown` look the same
on a graph and mean different things.
