# P241 — two controls, one name: the answer was in the drawing

**Raised by:** running `pnpm test:e2e` for the first time in an environment that
has a Postgres. It failed four tests on the first run.

**Closes the open question in** `journey.spec.ts` and `zwei-module.spec.ts`,
both of which have carried a `.first()` and a comment saying the choice belonged
to the client.

---

## What was wrong

P190-02 drew the sidebar's Punktemeldung row with `de.quiz.claim`, which at the
time read **CME-Punkte geltend machen** — the same words as the passed exam
screen's own button. One screen, two buttons, one accessible name.

It reached production. It is what failed **deploy 120's journey**, the first run
that ever got that far against the installation, and the workaround since has
been `.first()` in two specs plus a note that _"which of the two should go is a
decision about their layout."_

## The answer, from page 10

The decision had already been made, in the drawing nobody re-read:

```
        Abschlussprüfung bestanden!            Fortbildungsfortschritt
                                                  Modul 1 – Grundlagen
                    10 / 11                       Modul 2 – Diagnostik
              richtige Antworten                  Modul 3 – Therapie
                                                 CME-Punkte geltend machen
                       91%
      Sie haben 10 von 11 Fragen richtig beantwortet.
                 Fortbildung abschließen
```

`pdftotext -f 10 -l 10`, verbatim. The layout gives the two controls **different
names on one page**: `CME-Punkte geltend machen` is the _step in the progress
list_, `Fortbildung abschließen` is the _button_. Reading one key for both was
the mistake, and it was P190's.

So:

| key                       | was                         | is                        | drawn on          |
| ------------------------- | --------------------------- | ------------------------- | ----------------- |
| `player.reportingOpen`    | "Zur CME Punktemeldung"     | CME-Punkte geltend machen | the sidebar step  |
| `quiz.claim`              | "CME-Punkte geltend machen" | Fortbildung abschließen   | the passed screen |
| `quiz.claimWithoutPoints` | "Fortbildung abschließen"   | _deleted_                 | nothing, ever     |

`player.reportingOpen` was written in P95-01 and had never reached a screen —
`check:copy` carried it as known-dead. It has the drawing's wording and a caller
now. `claimWithoutPoints` was also baselined dead and is now word for word what
`claim` says in every case, so it goes.

**Nothing about the gate changed.** `claimPoints` is still
`courseComplete && completedAt === null`, still defined once in `App.tsx`, still
the pair `POST /completion` accepts. P195's three-state `ClaimRow` — locked,
open, and the certificate when it is done — is untouched.

## Why ten unit tests were green

Four widget tests cover the sidebar row and six cover that button, and every one
of them passed throughout, because each renders **one component**. The defect is
two components agreeing on a name, and it exists only on the assembled screen.

CLAUDE.md §9.13, in the shape the section was written for: an API test asserts a
function answers correctly, a unit test asserts a component renders correctly,
and neither can see the screen a physician is looking at.

## Three of the four failures were one failure

`verwaltung.spec.ts` failed twice with _"e2e-operator@… was asked for a code this
harness has no secret for"_, which reads as an unrelated auth defect and is not.
The TOTP secret is read off the enrolment screen on first sign-in and kept in a
module-level `Map` in `support/console.ts`. Playwright discards a worker process
after a failure, so the journey's failure took the Map with it, and the next file
signed in as an operator whose second factor was already enrolled with nothing to
answer.

Worth recording, because the shape recurs: **a failure count is not a defect
count.** One label turned 4 failures into 0.

(`pg_ctlcluster 16 main start`; `redis-server`) — `pnpm infra:up` cannot be used
here, there is no Docker daemon.

| `pnpm test:integration`   | **706 passed**, 24 files                         |

| `pnpm test:wp`            | 166 checks, 0 failed                             |
| lint / format / typecheck | clean                                            |
| `check:i18n`              | 961/961                                          |
| `check:copy`              | 337 strings, 13 baselined, 0 new                 |

Both `.first()` workarounds are removed, so the specs now assert the names
rather than tolerating the ambiguity — and `zwei-module` additionally asserts
that the sidebar step is **not** a control before the exam is passed, which is
the §9.2 half the old single assertion could not express.
