# P72 — the seeds point at a domain that does not exist

Asked for on 13.08, with four real 1080p recordings attached:

> _"make all of the data, images, videos and so on, real ones, no fake urls.
> create real data to test real data."_

The e2e fixtures were dealt with in P71-02. This ticket is the other half, and
it is the half the client has actually been looking at.

---

## What is fake today

Three seeds write media URLs on a domain nobody owns:

| Seed             | Writes                                                                                      |
| ---------------- | ------------------------------------------------------------------------------------------- |
| `medice-adhs.ts` | `https://media.example.org/adhs-akademie-adult/<n>.m3u8`, `-720.mp4`, `-360.mp4`, `<n>.pdf` |
| `ds-default.ts`  | `https://media.example.org/<slug>/<n>` renditions                                           |
| `ds-demo.ts`     | the same shape                                                                              |

`media.example.org` does not resolve. So every seeded course on every
installation has a player that cannot play and a Mediathek whose materials
cannot be downloaded — which is what the console screenshot of 13.08 shows,
three `media.example.org` rows under **Videoquellen**.

It is not a hidden defect: it was a deliberate placeholder, on the reasoning
that a seed cannot ship gigabytes of video. That reasoning was right about the
repository and wrong about the outcome, and it is the same shape as P70-01 —
something correct in the repository that leaves the installation broken.

Stamp and signature are the same: 1×1 placeholder PNGs, so a seeded course
renders a Teilnahmebescheinigung with an empty stamp box.

## What "real" should mean here

Not a URL on somebody else's CDN — that is a second fake with a licence
problem attached. The platform already has the right home for course media: its
own bucket, addressed as `s3://<customerId>/courses/<id>/<file>`, signed per
object at play time.

So the seed should **upload**, not link:

1. Ship one real recording in `packages/seed/media/` (the client has supplied
   four; `fortbildung-modul.mp4` is already committed under `apps/e2e/fixtures`
   and can move or be shared).
2. On seeding, if object storage is configured, PUT it under the customer's own
   prefix and write the `s3://` reference — the same key shape
   `object-storage.ts` builds for a console upload, so the read path is
   identical to a real course's.
3. If object storage is **not** configured, write no sources at all rather than
   a URL that 404s. The console already says "Bei hochgeladenen Videos …" and
   the player already says a section has no video; both are honest. A dead URL
   is the only option that lies.

The same recording can serve every module — a seed does not need five distinct
films to be real, it needs media that plays.

## Why this is its own ticket

It touches every seed, it adds an upload step to a code path that currently
only writes SQL, and it needs a decision about repository weight (one 9.8 MB
file, or a smaller re-encode). None of that belongs inside the P71 player fix.

## Acceptance criteria

- [ ] No seed writes a URL on a domain the platform does not control
- [ ] A seeded course on an installation with object storage plays
- [ ] A seeded course on an installation without it shows "no video" rather than
      a broken one
- [ ] The MEDICE course's Mediathek materials resolve, or are absent
- [ ] `grep -r "example.org" packages/seed/src` returns nothing

## Deliberately not done

**A real stamp and a real signature in the seed.** Those are credentials. See
`apps/e2e/fixtures/README.md` — committing somebody's professional mark puts a
reproducible copy of it in every clone and every CI runner. The placeholder
stays until MEDICE supplies the real ones through a channel that is not a git
repository, and S11 in `docs/show-stoppers.md` may yet make the whole embedded
stamp moot.
