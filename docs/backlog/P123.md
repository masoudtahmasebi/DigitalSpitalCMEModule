# P123 — Running the test pack against the codebase, before a person runs it

**Status:** built. Three findings, two fixed, one baselined with a check that
will not let the class grow.

---

## Why this phase exists

The test pack (DEP-5 … DEP-21) was written and handed over. Before asking a
person to walk 97 cases in a browser, the cases were walked against the source —
which is the cheaper instrument for anything derivable, and CLAUDE.md §9 exists
because _"the client found it by clicking, and it was derivable from source"_ has
happened this often.

Two of the three findings were found by the pack's own cases. That is the
argument for writing cases before running them.

## P123-01 — four screens a physician can stand in with no address

**Found by DEP-14 T09.4.** `#ds/mediathek` did not exist.

P82-04 gave the player, the evaluation and the Punktemeldung a fragment and
stopped there. The course overview's four tabs — Übersicht, Referenten,
Mediathek, Zertifizierung — stayed `useState`, so all four of §9.8's symptoms
were live on them: a reload dropped you back to Übersicht, Back left the course
entirely, and "look at the Mediathek" was a screenshot and directions.

It reads as three separate browser annoyances, which is exactly why the console
carried the same defect for nine phases before anybody wrote it down as one.

**Built:** `CourseTab` joins the `outline` route — a tab is which face of the
overview you are looking at, not a screen of its own, and encoding it separately
would let `#ds/mediathek` decode while the learner is inside a video. Segments
are the learner's own German (§5): `referenten`, `zertifizierung`, `mediathek`.
Übersicht keeps the bare `#ds` so every link sent since P82-04 still resolves.

Three wiring tests in `App.route.test.tsx`, not `route.test.ts` — §9.7, the
round-trip suite would be exactly as green with the whole feature deleted. Each
was watched to go red against its own sabotage: mount ignoring the tab, the
write-back hard-coding `overview`, and `hashchange` not applying it.

## P123-02 — 19 sentences written for physicians that no screen draws

`check:i18n` counts whether a German string has an English counterpart. It is
completely satisfied by a sentence nothing renders — §9.1's second form, a check
that covers less than it looks like it covers. So 19 of 291 strings were dead and
no gate had ever said so.

This is §9.3 one layer out from where that rule was written: there, a rule
exhaustively unit-tested and called from nowhere; here, a sentence worded,
reviewed, translated, and rendered by nothing.

**Built:** `scripts/copy-coverage.mjs`, in `pnpm verify` — not CI only (§9.11).
It imports the copy module rather than parsing it, and treats any object read
with a computed key (`de.tabs[entry]`) as wholly used, because a check that
over-reports is one nobody runs.

The 19 are a **baseline that only shrinks**, the same shape as `MINIMUM` in
`i18n-coverage.mjs`. A new dead string fails immediately; a baselined one that
becomes live also fails, telling you to remove the line. Both directions were
watched to go red.

Each entry is annotated with a decision rather than a count, because §9.3 is
explicit that a hit is not automatically a bug. `player.examInModule` is the
case in point: P95-01 wrote it so three identically-named Lernerfolgskontrolle
rows could be told apart, and the sidebar already nests exams under their module,
so the ambiguity does not arise. Wiring it would have invented a screen.

Three entries are marked **raise** rather than obsolete, and are genuine gaps
somebody other than me should decide the wording for (§7):

- `signedOut.expiredTitle` / `expiredMessage` — nothing distinguishes a session
  that expired mid-course from a token that never arrived;
- `gate.lockedHint` — a locked section says _Gesperrt_ and not what opens it;
- `content.videoUnsupported` — a browser that cannot play the video says nothing,
  which is DEP-20 T15.1's whole subject;
- `quiz.claimWithoutPoints` — a nought-point course still offers to claim points.

## P123-03 — a disabled button with no reason, and the sentence for it already written

**Found by DEP-15 T10.4.** `ready` requires the consent checkbox, so an untouched
box is a dead "Fortbildung abschließen" and the screen said nothing about why.
`completion.consentRequired` — _"Bitte stimmen Sie der Übermittlung zu."_ — had
been written for precisely this and was one of the 19.

§9.4, and the cheapest possible fix: render the sentence that already existed.
Held back until the name fields are filled, because an instruction that is true
too early reads as an error about a field the physician has not reached.
