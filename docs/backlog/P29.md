# P29 · Driving the real browsers, and the gate that could not be passed

> can you write and run tests that tests the whole system from start to the end,
> and if there are any issues, please fix it until the whole system is complete
> based on best practices and refactors?

P28 walked the whole system over HTTP and found three defects. This one walks it
in **a real browser**, against a real Postgres, a real API and a real video —
and finds the one thing an HTTP test structurally cannot see.

The API journey suite posts watched intervals. It therefore tests what the
server does with intervals it is handed. It cannot test **whether a `<video>`
element playing to the end produces the intervals that satisfy the gate**, and
that turned out to be the question that mattered.

---

## P29-01 · A learner could watch every frame and never be allowed to finish — **done**

- **Estimate:** 5 h · **Review gate: human — assessment, certificates**

A real 25-second WebM, played end to end in Chromium, through the real portal,
credited **96 %**. `required_watch_percent` defaults to 100 and is 100 on
`adhs-akademie-adult`, MEDICE's accredited course. The gate was not strict. It
was **unreachable**: a physician could watch an accredited Fortbildung from
beginning to end, repeatedly, and never be permitted to complete it — no CME
point, no Punktemeldung, no certificate, and nothing on screen explaining why.

Four independent losses, each individually invisible.

| Loss               | Where                                                                           | Size             |
| ------------------ | ------------------------------------------------------------------------------- | ---------------- |
| The head           | The interval opened at the first `timeupdate`, not at `play`                    | ~0.26 s          |
| The tail           | It closed at the last `timeupdate`, not at `pause`/`ended`                      | ~0.04 s          |
| Every flush        | `closeOpen()` then `drain()` lost the boundary; playback resumed a sample later | ~0.26 s **each** |
| The final fragment | A tail shorter than `MIN_SEGMENT_SEC` was discarded as noise                    | up to 0.25 s     |

On the 25 s demo that is 96 %. On a 25-minute module flushed every fifteen
seconds it is roughly a hundred boundaries — still short of 100, still
unfinishable, and now spread thinly enough that no one would find it by
staring at the numbers.

### The fix, in the two places it belongs

**The client reports what was actually watched** (`watch-tracker.ts`,
`VideoPlayer.tsx`). `play` and `pause`/`ended` now bracket the interval, so the
element's own position closes both slivers; and a `#resumeFrom` boundary
survives a close, so playback that simply carried on across a flush is one
interval rather than two with a hole. Continuity is forward-only and bounded by
`SEEK_TOLERANCE_SEC`, so a rewind never bridges and a seek never does; the
sub-threshold noise filter now exempts an interval that _continued_ one, because
that is a tail, not a stray event. `seeking` is deliberately still not observed —
`currentTime` is already the destination by then, and observing it would credit
material nobody watched.

**The domain stops calling the measuring instrument a hole**
(`watch.ts`). Even a perfect client cannot report `[0, duration]` exactly: `play`
fires a fraction in. `watchedPercent` now snaps each **end** of the union to the
content's bounds when it lands within `BOUNDARY_TOLERANCE_SEC` (0.5 s) of them.

That is a compliance-relevant change and it is deliberately narrow:

- **Endpoints only.** A gap in the middle stays a gap, at any size. Flooring
  still refuses to round 99.6 % coverage up — the existing test says so and
  still passes. Flooring and snapping answer different questions.
- **Half a second**, absolute, not a percentage. A percentage would scale to
  fifteen seconds on a 25-minute video; half a second cannot hide content at
  either end of anything.
- **Not applied to `maxWatchedPosition`.** Snapping the far end there would
  raise the forward-seek ceiling to the end of the video on the strength of a
  rounding error — the one thing the ceiling exists to prevent.

**Acceptance criteria**

- [x] A real browser playing the real video end to end stores
      `[{startSec: 0, endSec: 25}]`, 100 %, `status = completed`.
- [x] Six tracker cases in the units the bug occurred in: continuity across a
      flush, a whole-video watch across three flushes, and four refusals — a
      seek, a rewind, a pause longer than a playback step, and a resume from the
      same position.
- [x] Six domain cases for the tolerance, including _never closes a hole in the
      middle, however small_ and _does not credit an unwatched course_.
- [x] Deliberate-violation probe: reverting the continuity rule fails two
      tracker tests. Confirmed, then restored.

## P29-02 · The consent checkbox could never appear — **done**

- **Estimate:** 3 h · **Review gate: human — GDPR**

`CompletionScreen` draws the Einwilligung checkbox only when the project has
both `privacyPolicyUrl` and `privacyPolicyVersion` — correctly, since a consent
record naming no document proves nothing. `@ds/domain` parses and validates
both. `enrolments.consent_document` stores the version. The widget reads it on
every completion.

**Neither field was in `contracts/openapi.yaml`, and neither was in any form.**
So the checkbox was never drawn, and `consent_document` was empty on every
completion the platform had ever recorded — including the one this session
produced in a real browser before the fix.

Whether consent is even the right lawful basis for reporting a CME point is a
question for the client's DPO. What is not in question is that the platform
_designed_ for demonstrable consent under Art. 7(1), built the mechanism, and
left it unreachable.

Seven branding fields were in that state, not two: `catalogTitle`,
`catalogIntro`, `catalogHeroImageUrl`, `catalogSealImageUrl`, `catalogSealAlt`
and the consent pair. All seven are now published in the contract and editable
in the project settings form, with the pair guarded — the save button refuses a
half-filled pair rather than letting an operator save "successfully" and find
the checkbox still absent.

The **Erscheinungsbild** screen stays the font upload alone (a file needs its
own endpoint) and now says where the rest lives, so an operator does not hunt.

**Acceptance criteria**

- [x] All seven fields in the contract, the regenerated SDK and the form.
- [x] A blank field is omitted rather than stored as an empty string.
- [x] Half a consent pair disables the save and says why.
- [x] Verified in a real browser: set the pair in the console → the checkbox
      appears on the completion screen → `consent_document` holds the version.

## P29-03 · MEDICE's own login page was settable nowhere — **done**

- **Estimate:** 2 h · **Review gate: human — auth**

`projects.login_url` exists (migration 0028, with an HTTPS `CHECK`),
`resolve_project_signin` returns it, and `GET /tenants/{slug}` branches on it to
answer `external` instead of `portal` — which is what makes `/medice` link to
MEDICE's WordPress login rather than showing the portal's own password form.

The column was **absent from `apps/api/src/db/schema.ts`**, and that is exactly
why nothing could write it: Drizzle only knows the columns declared there, so
the column was invisible to every query this application builds. Every project
answered `kind: portal` whatever the customer actually used.

Now on `ProjectUpdate`, `ProjectSummary` and the console form. The DTO enforces
HTTPS as well as the database CHECK — `z.string().url()` accepts `http://`, so
an operator who typed one got a 500 from the driver instead of a sentence naming
the field. Both statements are load-bearing: the constraint makes it true of
every row however written, the DTO makes it legible to the person who can fix it.

**Acceptance criteria**

- [x] `PATCH /admin/projects/{slug}` stores it and `GET /tenants/{slug}` then
      answers `kind: external` with the URL — asserted unauthenticated, as an
      anonymous visitor is.
- [x] A non-HTTPS URL is refused with 422, not 500.
- [x] Verified in a real browser through the console.

## The pattern, now worth naming as a rule

Seven defects across P28 and P29 have the same shape: **a mechanism fully built
and reachable through no supported interface.**

|                              | Built                                           | Missing                        |
| ---------------------------- | ----------------------------------------------- | ------------------------------ |
| `courses.vnr`                | column, EIV worker, certificate barcodes        | write path                     |
| `projects.identity_provider` | column, CHECK, guard, provider registry         | write path, then console field |
| `projects.login_url`         | column, CHECK, SQL function, portal branch      | Drizzle column                 |
| `branding.privacyPolicy*`    | domain grammar, widget checkbox, storage column | contract, form                 |
| five other branding fields   | domain grammar, widget rendering                | contract, form                 |

A sweep comparing every `courses` and `projects` column against the admin DTOs
now reports **only binary-upload columns and server-derived ones**, which is the
correct residue. That sweep is cheap and worth repeating whenever a column is
added — the query is in this ticket's commit message.

The lesson for the test suites is the sharper one. Every one of these passed
unit tests, passed integration tests, and would have passed a code review: the
code that was there was correct. What was missing was a _caller_. Only a test
that starts where a human starts — an empty database, a browser, a real video —
asks whether a caller exists.
