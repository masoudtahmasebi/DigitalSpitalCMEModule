# P76 — the sweep after P75, and what a blind scanner was hiding

Not a report from a browser. This is the standing end-to-end pass the client
asks for after each batch of fixes, and both items came out of running
`scripts/unused-rules.mjs` — the §9.3 check — and then doing the part the
script's own output says has to be done by a person: **looking at each hit.**

The two are in the order they were found, because the first one is the reason
the second was findable at all.

---

## P76-01 · a scan that skipped a file it mistook for binary

`scripts/unused-rules.mjs` greps for callers of every exported rule in
`packages/domain`. It ran `grep -rn`, without `-a`.

One NUL byte anywhere in a file makes `grep` treat the whole file as binary: it
prints `binary file matches` to stderr and **no matching lines at all** to
stdout. Piped into `wc -l`, that is zero. Every caller in such a file is
invisible.

`apps/widget/src/branding.ts` was such a file. It builds a cache key from two
strings and used a NUL as the separator — a sound choice, because no API base
or project slug can contain one, so no pair of inputs can collide by
concatenation. It was written as the **literal byte** rather than as `\u0000`,
which made a perfectly ordinary TypeScript file binary to every tool that reads
bytes: `grep` without `-a`, `git diff` (it says only _"Binary files differ"_ —
so a change to this file could not be reviewed), and any future scanner nobody
has written yet.

The measurement, which is the point:

```
grep -rn  "parseBranding" apps packages … | wc -l   → 20
grep -arn "parseBranding" apps packages … | wc -l   → 23
```

Three callers did not exist as far as the check was concerned. `parseBranding`
was not itself at risk — it had seventeen other callers — but a rule whose only
callers lived in that file would have been reported as dead, and the reasonable
next step on a §9.3 hit is to delete it.

Both halves are fixed, and they are different fixes for the same defect:

- the byte is now the escape `\u0000`, with a comment saying why the separator
  is a NUL and why it must never be written literally again — the file is now
  text to everything, and `git diff` shows it;
- the scanner passes `-a`, so a file it cannot parse can never again silently
  count as a file with no callers in it.

The second is the one that matters for next time. This is §9.1's third form —
_the check is green because of what it is not scanning_ — and it had been true
of this check since it was written in P39.

A repo-wide scan now confirms no tracked source file contains a NUL.

### Acceptance criteria

- [x] No tracked `.ts`/`.tsx`/`.mjs`/`.js` file contains a NUL byte
- [x] The separator survives as `\u0000` with the reasoning recorded at the line
- [x] The scanner reads files `grep` would otherwise skip
- [x] Red-checked by counting `parseBranding` both ways: 20 against 23

## P76-02 · two rules with no callers, each the wrong half of a live pair

With the scan no longer blind, seventy-eight names came out. Filtering the type
aliases — a type cannot have a caller, so it cannot be a §9.3 hit — left
twenty-five rules, of which four had non-obvious answers and two were real:

| Rule                                                | Verdict                                                  |
| --------------------------------------------------- | -------------------------------------------------------- |
| `mediaSourceProblems`, `backoffMinutes`             | called — `authoring.ts:137`, `delivery-retry.ts:139`     |
| `addCalendarDays`, `berlinDateOf`, `endOfBerlinDay` | called from `eiv.ts`; the scan does not see same-package |
| `totpCounters`                                      | called from `verifyTotp` one function down               |
| **`watchedSeconds`**, **`clampSeek`**               | **no callers anywhere — removed**                        |

Neither was an unenforced rule, so neither is §9.3 as written. They are its
mirror image, and the mirror image is worse: **each is the disfavoured half of
a pair whose other half is called everywhere.** The rule is enforced; what sat
beside it was a second answer to the same question, one import away from any
caller, with the more inviting name of the two.

### `watchedSeconds` — the function that caused P68-02

> `/** Total seconds covered by the union of the segments. */`

Raw, uncapped, no endpoint tolerance. Summing it across a course is precisely
what produced P68-02: the same stored segments reading **100 % per content and
99 % per course**, in one response, with the module marked complete, the
Lernerfolgskontrolle unlocked, and „Es fehlt noch: die vollständige
Videowiedergabe" on the Punktemeldung form — with nothing left to watch and no
way out of the state.

The fix at the time was `watchedSecondsWithin`, which applies the tolerance and
caps at the content's length, so CLAUDE.md §4 invariant 6 holds for this number.
But the function that had been wrong was left exported, with the docstring that
makes it sound like the primitive the other one is built from. Nothing would
have objected to the next rollup calling it, and the two disagree quietly —
which is the whole reason invariant 6 exists.

Removed. `mergeWatchedSegments` remains exported for anyone who genuinely wants
the intervals, and is honest about being intervals rather than a credited
figure. Its former test case now pins the property it was hiding: a segment
overrunning the duration credits the duration, not the overrun.

### `clampSeek` — a function whose every use would be a bug

It composed `seekCeiling` (segments → ceiling) and `clampSeekToLimit`
(target + ceiling → position) into one call. Both halves are called, on
**opposite sides of the API boundary and deliberately so**: the server turns
segments into `seekCeilingSec`, the client clamps against that number.
`clampSeekToLimit`'s own docstring already said why —

> the client is a renderer and recomputing the server's answer from its inputs
> is how the two come to disagree

— and a function that does both can only be called somewhere holding both,
which on the client means exactly that recomputation. So it was not merely
unused: any use of it would have been the defect the split exists to prevent.

Removed, with the reasoning left at the site as a comment, because the next
person to notice that the two halves compose neatly should find the argument
rather than the convenience.

### What replaced the tests

Not deletion. The cases move to the path the product actually takes —
`seekCeiling` then `clampSeekToLimit`, written out as two steps — so the tests
now have the shape of the real call sites, which is §9.7: a test of a rule
nothing calls proves nothing about the product.

Domain suite: **651 passing**, two more than before. Repo typecheck clean, which
is what proves nothing outside the domain imported either name.

### Acceptance criteria

- [x] Neither name is exported from `@ds/domain`
- [x] The reasoning is recorded where each used to be, not only here
- [x] The seek tests exercise the two-step boundary path
- [x] The P68-02 cap has an assertion of its own
- [x] `pnpm typecheck` clean across every workspace

## P76-03 · the section nobody can finish, said out loud

The P75 "Still open" item, and the half of the reported bug that P75-01 did not
touch.

P75-01 removed the way a _new_ content acquires a length larger than its file.
It could not repair the contents already stored, and it deliberately kept the
escape hatch for a length that cannot be measured — so the state the client
reported is still reachable, and on any course authored before that change it is
still **present**. The repository's state is not the installation's state
(§9.9): a fix to the form does not rewrite a row.

In that state the learner is told nothing at all. The gate asks for more seconds
than the video contains, so the bar cannot fill, the countdown cannot reach
zero, and the screen says „0 % der Fortbildung absolviert" after a complete
viewing. A physician has no way to tell that apart from their own browser being
broken.

### The rule, and why it only ever reports

`mediaLengthVerdict` in `@ds/domain` compares the authored length with the
file's own against the course's gate, and returns one of three answers:

| Answer        | Meaning                                                                   |
| ------------- | ------------------------------------------------------------------------- |
| `unreachable` | the gate demands seconds the file does not contain — the learner is stuck |
| `overrun`     | the file is materially **longer** than its authored length                |
| `ok`          | they agree, or there is not enough information to judge                   |

It adjusts nothing. The percentage that decides a CME point stays the server's,
computed from the authored length: a learner's browser quietly substituting the
file's own length would be the client deciding a compliance outcome (§4
invariant 1), and two physicians on different browsers could then get different
answers. The verdict exists to be **said**, to each audience that can act on it
(§9.10).

`overrun` is the quieter mistake and is deliberately not shown to the learner.
Nobody is blocked by it, so nobody will ever report it — and it means an
accredited module can be completed without watching the part that runs past the
authored figure. That is the operator's problem, and a learner cannot act on it.

### What each audience is told

**The learner**, directly under the progress card where the confusing number is:
what is wrong, both lengths, that watching on will not help, and who to ask. It
deliberately promises nothing about their points — the widget does not know
what will be credited, and inventing reassurance about a CME point is exactly
what invariant 1 forbids.

**The operator**, in the content form: that the stored figure disagreed with the
file, what each is, what it cost learners, and that **Speichern** applies the
correction. Without that last part the repair is invisible — P75-01 measures and
overwrites the field, so somebody who opens the form for an unrelated reason
sees a correct number, never learns the content was refusing to complete, and
leaves it refusing by navigating away.

That question needs its own function. `lengthsAgree` asks _"is this number
right?"_, which does not depend on the gate; `mediaLengthVerdict` asks _"can I
finish this?"_, which does. Answering the operator with the learner's rule would
stay silent about 590 seconds stored as 600 on a course gated at 80 % — correct
today, and wrong the moment somebody raises the gate.

### Red-checked

The domain tests would have passed unchanged on the player that never called the
rule — which is the player that shipped, and is §9.7 exactly. So the assertion
that matters is in `PlayerScreen.test.tsx`, and it was verified by severing the
call site while leaving the import and the arguments in place: one test fails,
naming the missing sentence, and the other 221 stay green.

### Acceptance criteria

- [x] A learner facing an unsatisfiable gate is told so, with both lengths
- [x] The notice appears only once the browser knows the file's length, and
      never on a course that is fine
- [x] It is judged against the course's own gate, not against 100
- [x] Nothing about the gate, the percentage or the credit changes
- [x] The operator is told the stored figure was wrong and that saving fixes it
- [x] Red-checked at the call site, not only in the rule

## P76-04 · every Postgres pool was one restart from killing its process

Found by CI, on the commit that carried P76-03. The **Integration tests** job
went red with twelve passing tests and this:

```
Vitest caught 1 unhandled error during the test run.
error: terminating connection due to administrator command   (57P01)
```

The identical commit had gone green in the sibling workflow run minutes
earlier, which is the tell: it is a race, and a check that answers differently
on the same input is not evidence either way (§9.1).

### The mechanism, which is not really about tests

`pg.Pool` holds connections open and idle between queries. When the server
closes one — a failover, a restart, an idle-session timeout, a firewall
dropping a quiet socket, or `DROP DATABASE ... WITH (FORCE)` in the migrator's
own suite — the pool emits `'error'`.

In Node, an `'error'` event on an `EventEmitter` **with no listener** is not
ignored. It is re-thrown as an uncaught exception.

Not one of the thirty-odd pools in this repository had a listener. Including
`apps/api/src/db/db.module.ts` — the long-lived pool behind every request. So
the same defect that shows up in CI as a flaky test is, on the API, a process
that dies when Postgres restarts underneath it: no failing request to point at
it, no stack in application code, nothing in the log but the process ending.

### The fix is a factory, not thirty listeners

`@ds/postgres` is a new package with `createPool`, `attachIdleErrorHandler` and
`attachClientErrorHandler`. It takes the whole of `pg.PoolConfig` — a factory
that models a subset is one somebody abandons the moment they need `max`, and
the way it gets abandoned is `new pg.Pool`.

It is a **report, not a decision**: query errors still reject their own promise
and reach their own caller, and `pg` already discards the broken client and
opens a fresh one on the next checkout. The only thing missing was somebody
listening.

Thirty-four call sites converted across the API, the migrator, the seeds and
the integration suites. `apps/e2e` is the one exception and keeps a hand-rolled
handler with the reason at the line: that package may not import a workspace
package at all, because `pnpm test:smoke` runs it against a real deployment
where a `dist/` was never built.

### Why a lint rule and not a note in CONTRIBUTING

Because the missing line is invisible. Nothing fails, nothing warns, and the
pool works perfectly until the day it does not — which is §9.3's shape exactly,
and a convention nobody can see being broken is one that will be broken. So
`no-restricted-syntax` refuses `new Pool` and `new pg.Pool` outright, and names
the replacement in the message.

Tests are **not** exempt, deliberately: the report that uncovered this was a CI
failure caused by a test pool, and exempting tests would exempt the exact case
that found it.

### What is verified, and what is not

Verified, and red-checked:

- the mechanism. `packages/postgres` has eight unit tests, two of which are
  controls asserting that an **unguarded** pool and client genuinely do throw.
  Without those the rest would pass against a `createPool` that did nothing;
- the lint rule. Restoring `new Pool` in `bootstrap-admin.ts` fails lint with
  the intended message, and passes again when reverted;
- that nothing else broke: 667 domain, 548 API unit, 222 widget, 140 admin,
  525 integration, every static gate.

**Not** verified: that this is what fixes the CI flake. The race would not
reproduce locally — the migrator suite ran five times clean with the fix, and
then **six times clean with the fix entirely reverted**. A slower, more
contended runner is evidently part of the recipe. So the honest claim is that
the hazard is removed and the mechanism is proven, not that the observed
failure was reproduced and cured. If it recurs, the unhandled error will no
longer be the cause, and the next report should say something different.

### Acceptance criteria

- [x] One factory; no `new Pool` outside the package that implements it
- [x] The API's pool reports an idle failure through the structured logger
- [x] Lint refuses the unsafe constructor, tests included
- [x] Controls prove the unguarded behaviour is fatal
- [x] The one exemption carries its reason at the line
- [ ] The CI race reproduced locally — could not be, see above

## Deliberately not done

**Repairing the stored durations from the server.** The API cannot measure a
video — that needs decoding tooling, and media transcoding is deferred scope
(CLAUDE.md §3). The measurement happens where there is already a decoder: the
browser. So the console reports and the operator saves.

**Making the scanner fail the build.** It reports names, and a hit is a
question for a person — six of this run's eight non-obvious hits were correctly
enforced code. Wiring it into `pnpm verify` as a gate would produce a red build
that the fastest way to fix is a spurious call. It stays a tool somebody runs
and reads.
