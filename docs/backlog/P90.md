# P90 — one button, one dialog, like WordPress

**Status:** in progress, 17.08.2026.
**Raised by:** the client, looking at the Videoquellen block —

> _"please make the mediathek and media selection like wordpress, why are there
> 3 options? i don't get it why I have to repeat everything multiple times, just
> one button to select the media, and then a popup opens shows already uploaded
> medias for that customer, or you can upload a new one, like wordpress"_

---

## What the three buttons actually were

They were not three ways to do one thing, which is what makes the report
correct rather than a misunderstanding. They were **three unrelated things
drawn as one row of equal buttons**:

| Button                     | What it did                                            | Added by |
| -------------------------- | ------------------------------------------------------ | -------- |
| **Video hochladen**        | opened the file picker, uploaded, appended a source    | P23-04   |
| **Aus Mediathek wählen**   | opened an inline panel of already-uploaded files       | P81-03   |
| **Videoquelle hinzufügen** | appended an **empty row** to type an external URL into | earlier  |

Each was added in a different phase, by the same reasoning each time — _the
thing this screen cannot do yet is X, so here is a button for X_ — and nobody
ever looked at the row afterwards and asked what it adds up to. Three buttons
of equal weight, in one place, with no statement of how they differ, is not a
choice a person can make; it is a puzzle.

The same row is repeated for the poster, the subtitles and the material, which
is the _"why do I have to repeat everything multiple times"_ half.

## What WordPress does, and why it is the right answer here

One **Medien hinzufügen** button opens one modal with tabs: _Mediathek_,
_Dateien hochladen_, _Von URL einfügen_. The important part is not the visual
style — it is that **the question is "which file?", and where the file comes
from is an answer inside that question**, not a decision to be taken before it.

That maps exactly onto what this console has: an object store, a per-customer
library, and a legitimate external-URL case (a customer already serving media
from their own CDN, and HLS manifests, which the hint text has always
mentioned).

## The work

- **`MediaDialog`** — one modal, three tabs, used everywhere a file is chosen.
  It replaces `MediaPicker`, which was the inline panel.
- **One button** in `SourcesEditor` and in every `UploadField` (poster,
  subtitles, material).
- **`MediaPicker` is deleted.** Its tests move to `MediaDialog.test.tsx` — the
  properties they pinned are still properties, they just have a new home.

### The empty library is the case to get right

A customer's first course opens a library with nothing in it. WordPress lands
you on the Mediathek tab and leaves you looking at an empty shelf; here the
empty state carries the button that switches to the upload tab, so the next
action is on the screen rather than in another tab (§9.4).

The tab does **not** default differently when the library is empty. It was
tempting — and it would make the post-deploy journey depend on how much the DS
Test tenant happens to hold, which is P89-03's mistake in a new place.

### A modal has obligations, and `ui.tsx` already wrote them down

`ConfirmButton`'s header says why the console had avoided modals:

> _A modal has to trap focus, restore it on close, and be dismissible by
> Escape, and getting any of those subtly wrong makes the console unusable by
> keyboard._

That is a reason to implement them, not a reason to have no dialog — a media
browser is not a one-sentence confirmation. All three are implemented and all
three are tested, because an untested focus trap is the defect that reaches
somebody who cannot use a mouse.

### Two things moved, and neither is cosmetic

`MediaDialog` is rendered **by** `UploadField` and needs the upload that lived
in it — a cycle between two component modules. So the plumbing left the
component:

- **`src/uploads.ts`** — `runUpload`, the SRT→WebVTT conversion, `ACCEPT`,
  `LIBRARY_KIND`, `describeUploadFailure`. None of it was ever a component.
- **`UploadProgress` → `ui.tsx`**, for the same reason: two components render
  it and one of them renders the other.

`Button` gained an optional `id`, used once: the dialog's opener appears on the
sources, the poster, the subtitles and the material of one form, so the browser
suite needs a handle that does not depend on render order.

### The hint that described a different field

The first version showed `videoUploadHint` in every tab, so an author uploading
a PDF was told _"MP4 oder WebM, bis 2 GB"_. One dialog serving four fields has
to say what **this** field takes — `media.uploadHints` is per purpose. A hint
describing another field is worse than none: it is a confident wrong answer at
the moment somebody is deciding whether their file will be accepted.

## Acceptance criteria

- [x] One button opens the media dialog, everywhere a file is chosen.
- [x] The dialog lists this customer's already-uploaded files, filtered to what
      the field can accept.
- [x] A new file can be uploaded from inside the dialog and is assigned when it
      lands.
- [x] An external URL can still be supplied — the case the empty row served.
- [x] Escape closes it, focus is trapped inside it and restored on close —
      each asserted, and each watched to go red with the handler removed.
- [x] The Mediathek screen keeps working and shares the same `useMediaLibrary`.
- [x] `pnpm verify` green: 195 console tests, lint, typecheck, `check:i18n` at
      645/645 with English parity, `check:roles`.
- [ ] Both browser journeys pass — they upload through this control.

## Not done

- **Multi-select.** WordPress lets you pick several files at once for a
  gallery; here the only field that takes more than one is the video source
  list, and renditions of one recording are added deliberately one at a time.
  Worth revisiting if somebody asks; not invented ahead of the ask.
- **The certificate stamp and signature stay outside**, as in P88-02: they go
  through `adminSetCertificateAssets` as base64 on the course row rather than to
  object storage, because they are per-course compliance artefacts.
