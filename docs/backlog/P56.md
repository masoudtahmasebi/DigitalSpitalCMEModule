## P56-01 · An accredited course could be configured to hand back the answer key · 2 h

**Status: done.** Touches assessment — human review.

### What was wrong

`packages/domain/src/assessment.ts` has carried this sentence since P4-02:

> _"no endpoint ever returns a correctness marker for a CME-certified course."_

It was a comment. What the API actually did was read
`courses.reveal_correct_answers` and honour it:

```ts
...(course.revealCorrectAnswers ? { perQuestion: result.perQuestion } : {})
```

No route writes that column — but a seed, a support script or a future admin
field can, and one `UPDATE` was enough:

```
reveal_correct_answers = false → keys: attemptNumber, correctCount, …
reveal_correct_answers = true  → keys: …, perQuestion
  perQuestion: {"e1de4362-…":false,"8a01700f-…":false, …}
```

One boolean per question, on a course awarding CME points, with unlimited
retries. Four sittings is the whole answer key, and the Lernerfolgskontrolle it
would void is a condition of the Anerkennung — the Bescheid requires 70 % of
questions answered correctly, which means answered, not eliminated.

This is CLAUDE.md §9.3 exactly: a rule written in a file that near-total
coverage made _feel_ done, called by nothing.

### What changed

**`mayRevealCorrectAnswers` in `@ds/domain`**, beside the scorer, because it is
the same compliance question read from the other end. A course awarding points
never reveals, whatever its column says. A course awarding none may, if it asks
— that is the case the setting exists for, and immediate feedback on
unaccredited material is the point of it.

**And the database refuses to hold the combination** (migration 0039,
`courses_no_answer_key_for_points`). Two layers because the failure modes
differ: the service protects the _response_, the constraint protects the _row_.
A stored `true` that never takes effect is a setting somebody eventually "fixes"
by making it work.

Keyed on points and not on "has a VNR": the VNR routinely arrives weeks after a
course is authored (P7-07), so keying on it would leave a window in which the
same course legitimately revealed answers and then stopped.

### The test that was asserting the bug

`assessment.service.test.ts` had a case named _"includes per-question
correctness when the course does reveal answers"_ — against a fixture worth **4
CME points**. It passed, and it was wrong: it encoded the defect as the
expectation. It now covers the point-free course, and a second case covers the
accredited one.

Verified red: reverting `mayRevealCorrectAnswers` to return the raw flag turns
two domain cases and one service case red. The journey suite asserts the other
layer — that the database refuses the `UPDATE` on its own accredited course.

### Acceptance criteria

- [x] A course awarding CME points never returns `perQuestion`, whatever the
      column says
- [x] A point-free course that asks for it still gets it
- [x] The database refuses to store the combination, asserted on the journey's
      own accredited course
- [x] Verified red at both layers
- [x] `pnpm verify` green; 474 integration tests green
- [ ] **Human review** — assessment. The reviewer's question is whether
      "awards points" is the right line, or whether the platform should simply
      never reveal.

## P56-02 · A refusal from the PDF route was labelled as a PDF · 0.5 h

**Status: done.**

`GET /courses/{slug}/certificate/pdf` declared `@Header("content-type",
"application/pdf")`. Nest applies that **before** the handler runs, and
`res.json()` sets a content type only when nothing has set one — so every
refusal from that route went out as a problem document wearing a PDF's
content type:

```
GET /courses/qa-quiz-10/certificate/pdf
  → 409  content-type: application/pdf; charset=utf-8
         {"type":"https://docs.ds-education.de/errors/conflict", …}   337 bytes
```

A browser offers to save a broken file. A client that dispatches on the header
hands three hundred bytes of JSON to a PDF renderer. And the case is not exotic:
it is what a physician gets for opening the certificate link before the
Zertifizierung is finished, which is the ordinary way to arrive there.

**Fixed in the filter, not in the route** (§9.11 — fix the class). Any route
declaring a content type has the same bug the moment it throws, and the filter
is the one place that knows the response is no longer what the route promised.
It now sets `application/problem+json; charset=utf-8` on every error — which is
what `contracts/openapi.yaml` has claimed since its first comment line, so this
is also the API starting to agree with its own contract.

The redundant decorator is gone from the certificate route; `StreamableFile`
sets the type on the success path, which is the only path that has one.

### Acceptance criteria

- [x] A refusal from the PDF route is `application/problem+json`, and really is
      a problem document
- [x] A successful download is still `application/pdf` with its filename and
      `no-store`
- [x] Every error path — `AppError`, framework exception, unhandled — carries
      the type, asserted separately
- [x] Verified red by removing the header

## What Section 5 confirmed as already correct

- **5.1 — no answer key in the quiz payload.** Ten questions, forty options,
  and the raw JSON contains none of `isCorrect`, `is_correct`, `"correct"`,
  `correctAnswer`, `correctOptionId`, `answerKey`, `solution` or `explanation`,
  against a database holding ten correct options for that content.
- **5.2 — a failed attempt says how many, never which.** `correctCount`,
  `totalCount`, `scorePercent`, `passed`, `passThresholdPercent` and nothing
  else.
- **5.3 — the threshold is `>=` on a floored integer.** 6/10 → 60 %, fails;
  7/10 → 70 %, passes; the same 70 % against a threshold of 71 fails.
- **5.4 — a score cannot be asserted.** `passed: true, scorePercent: 100` in
  the body is ignored and the attempt is scored from the selections; progress
  cannot be posted against a quiz content (422); completion re-derives every
  condition and refuses.
- **5.5 — retries are unlimited and every attempt is recorded**, with its
  answers and per-question correctness in `quiz_answers` — server-side only.
  The pass is **best-of, not latest**: a physician who passes and retries out
  of curiosity keeps the pass.
- **5.6 — passing completes the chapter and opens the next.**
- **5.7 — the Evaluationsbogen is a hard gate.** Completion refuses while it is
  outstanding and names it; a second submission is refused rather than
  overwriting the first; the certificate is unreachable until the completion
  stands.
