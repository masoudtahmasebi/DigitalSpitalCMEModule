# P240 — the post-deploy journey tested the default branch, not the deployment

Found by deploy **142**, which deployed `699300b` correctly and then failed its
own browser suite against a spec from a different commit.

```
Error: the Lernerfolgskontrolle was offered before its module's video was
       watched (P87-04)
Locator: getByRole('button', { name: 'Fortbildung pausieren' }).first()
  281 |   learner.getByRole("button", { name: "Fortbildung pausieren" }).first(),
```

That locator had been migrated by the very commit being deployed — P239 turned
the player's control into a pair, so on a stopped video it correctly reads
**Fortbildung fortsetzen**. The failure quotes the **old** label at the **old**
line number.

## What was actually happening

|                                                                                                   |                                                                         |
| ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `origin/main` line 281                                                                            | the migrated regex, `/^Fortbildung (pausieren\|fortsetzen\|starten)$/u` |
| `origin/claude/education-platform-roadmap-3vgrqh` (the **default branch**) at `3b592dd`, line 281 | `name: "Fortbildung pausieren"`                                         |

The smoke job's checkout was:

```yaml
- uses: actions/checkout@v7
```

No `ref`. `actions/checkout` defaults to `github.ref`, and on a `workflow_run`
event that is the repository's **default branch** — which on this repository is
`claude/education-platform-roadmap-3vgrqh`, not `main` (§9.9b). The default
branch last moved on 3b592dd, days ago.

So every post-deploy journey since has driven the newly deployed installation
with whatever spec that branch happened to hold.

## Why this is the same root as P175-01, and why it survived it

P175-01 found exactly this property of `workflow_run` — that `github.ref` is the
default branch and not the trigger — and fixed the **guard** that decides what
may be deployed, replacing `github.event.repository.default_branch` with the
literal `main`. It did not look at the **checkout** that decides what tests it.

The guard answers "may this be deployed". The checkout answers "what is the
deployment checked against". One was fixed and the other was not, and the second
is the one that had been quietly weakening every deploy's evidence.

## P240-01 — the spec comes from the deployed commit

```yaml
- uses: actions/checkout@v7
  with:
    ref: ${{ github.event.workflow_run.head_sha || github.sha }}
```

The `|| github.sha` fallback is the deploy job's own, one hundred lines up, and
for the same reason: on a `workflow_dispatch` there is no `workflow_run`, and an
empty `ref` would fall back to the default branch — which is the defect being
removed.

## What this does **not** mean

The deployment itself was correct and is correct. From the deploy's own smoke
step, read from outside the host:

```
{"status":"ok","database":true,"redis":true,"commit":"699300b","version":"0.1.593"}
Serving 699300b, which is 699300baf3ffdeca1e54f96bc92d44b49fc9fd29 —
verified from outside the host.
```

`journey.spec.ts` — the full learner journey, build a course, watch it, sit the
exam, download the Bescheinigung — **passed against production** in the same
run. The failure was one stale assertion in the second spec, and the product it
was pointed at is the one that shipped.

## The uncomfortable part, stated rather than left implicit

A green post-deploy journey has, until this commit, been **weaker evidence than
it read as**. It proved the deployed installation satisfied the default
branch's expectations, which is only the same question when the two happen to
agree. They agreed for a long time, which is exactly why nobody noticed — §9.1
at the level of the pipeline rather than of a test.

Deploys 139, 140 and 141 were green under this defect. Their _deployments_ are
independently evidenced by the smoke step's commit comparison (P155-02), which
is a different check and was not affected.
