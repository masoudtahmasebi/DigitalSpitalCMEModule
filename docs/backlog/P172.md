## DEP-33 — Zurück zur Übersicht left the address behind

> _"Clicking Zuruck zur Ubersicht renders the course list view but does not
> update the browser route/URL. A page refresh on the course list therefore
> redirects the user back to the previously active tab."_

The reporter's suspected root cause is right, and worth stating precisely: the
button called `setSelected(undefined)`, which unmounts the course tree and
renders the catalogue. The fragment write-back effect lives **inside** that
tree, so nothing wrote the address on the way out — and the fragment is what
decides which course mounts at all (`decodeCourseSlug`), so a reload walked
straight back in.

CLAUDE.md §9.8 lists the three symptoms that always arrive together; this is the
third, and the only one that needs an F5 to see.

`clearCourseFragment()` in `route.ts` removes the fragment, and **only when it
is one this router wrote**. `<ds-lms>` mounts inside a customer's WordPress
page: a learner may have arrived at `…/fortbildungen#kontakt` from the theme's
own menu, and clearing that would move a page under them. It returns whether it
did anything, so the tests can tell the two apart.

Removing the fragment rather than writing a catalogue route, because the
catalogue **is** the page: there is no `WidgetRoute` for it and there should not
be — the absence of a course fragment already means "the catalogue", which is
what a first visit looks like. `replaceState`, like every other write here.

Tested twice over, deliberately: `route.test.ts` covers the rule (ours cleared,
the host's untouched, no fragment at all), and `App.route.test.tsx` covers that
the **button calls it** — the round-trip test would pass unchanged on a widget
that never did, which is §9.7 and is the defect itself. Watched red with the
call removed.

## DEP-32 — The video-percentage line is gone from the progress card

> _"Confirmed by Philipp — the video percentage info is not needed in the
> widget."_

`8 % der Videoinhalte angesehen (erforderlich: 100 %).` removed from
`ProgressCard`. The card answers one question — how many modules are done — and
a second percentage measured against a different denominator beside it is two
answers to "how far am I".

The figure has not gone anywhere a learner needs it: the Zertifizierung tab
states the requirement as an accreditation condition, and the player's own
progress card reports coverage while a video is running, which is where a
percentage of _video_ belongs.

`ProgressPanel`'s `footnote` prop stays — the panel is a primitive and this is
one caller's decision. `de.overview.watchProgress` is deleted, because a copy
key nothing renders is the shape §9.3 is about.

The ticket says "sticky progress widget". The sticky panel has never drawn this
line (its own comment says why); the line was on the **inline** card, which is
what the client's screenshot shows and what the ticket's element list describes.
Same card, one name.

## DEP-31 — Two mobile layout issues below 640 px

**The Inhalte row.** Title and duration shared a line with the duration hard
right, which is the desktop drawing. Below `sm` the mobile export stacks them —
title, topics, then the duration on its own line — because at 430 px a
right-aligned duration squeezes a German compound title into three wrapped lines
to save one. The change is one flex direction on the content column, not a
second tree: the arrow stays beside the title in both.

**The tab buttons.** `rounded-full` at full width is a 24 px sweep on a 430 px
bar, which reads as a chip rather than as stacked navigation. They now use the
same `1.25rem` family as every other teal block here, with the top-right still
square so the shape stays recognisably one family.

## DEP-30 — The CTA orange

> _"Color used: #f0912e / Color to use: #ff9800"_

`#ff9800` is Material orange 500 exactly. The client gave one value; the other
four steps of the ramp were mixed from the old hue and would have left a button
that hovers from the new orange to the old one, so they are that ramp's own
neighbours rather than four numbers invented here: 50 `#fff3e0`, 100 `#ffe0b2`,
600 `#fb8c00`, 700 `#f57c00`.

Only the **fallbacks** change. `--ds-cta-*` is what a customer's branding sets,
and nothing sets it today — `grep -rn "ds-cta-500"` over the API, the migrations
and `@ds/domain` returns nothing — so these values are what every installation
renders. One token, so every element the ticket lists (the CME-Punkte badge, the
Fortbildung fortsetzen buttons, the orange icons) moves together.
