# P146 — The sweep P145 owed, run by the verifier instead of by me

`CLAUDE.md` §11 was added in this session. Its rule 11 says: after fixing a
defect with a shape, search the whole repository for that shape **before**
calling it done, and state the search and its full result list.

The first thing the §11 verifier pass did was catch me not doing that, on P145,
the commit immediately before. Recorded here rather than quietly fixed, because
the point of §11 is that the miss is visible.

---

## P146-01 — Two of P145's five routes were moved on a false justification

**Status:** done (reverted).

P145 put `@NoAmbientTransaction()` on five upload routes, on the grounds that
each "calls the object store" and so holds a connection across a network round
trip. That is true of three of them. It is false of `POST media/:id/view` and
`POST courses/:slug/uploads/view`:

```
$ sed -n '/readUrl(/,/^  }/p' apps/api/src/shared/object-storage.ts
  readUrl(key: string, ttlSec: number, now: Date): string {
    return this.presigner.presignGet(key, ttlSec, now);
  }
```

`presignGet` is an HMAC over a string. It is synchronous, returns a `string`,
and touches no network. Those two routes hold a connection across **nothing** —
so moving them gave up the request's atomicity for no benefit whatsoever.

Both are back on the ambient transaction, and the controller now says why at the
place somebody would ask.

This is the exact failure §11 exists for: a sentence that was true of the
neighbouring case, applied to a case where it was false, and fluent enough that
nothing questioned it.

## P146-02 — Four request handlers still hold a transaction across a network call

**Status:** not fixed. Recorded with evidence.

### The search

Two greps, and the intersection is the answer:

```
$ grep -rl "@TenantDb() db: Db" apps/api/src/modules --include=*.controller.ts
  → 11 controllers, 78 routes on the ambient transaction

$ grep -rn "fetchImpl(" apps/api/src --include=*.ts | grep -v test
  → 7 files that make an outbound call:
      backup/store.ts                            (no request, no connection)
      shared/bucket-cors.ts, bucket-lifecycle.ts (deploy tooling, no request)
      shared/object-storage.ts                   (P145 — three routes fixed)
      modules/admin/media-check.service.ts        ← reached from a request
      modules/certificate/certificate.archive.ts  ← reached from a request
      modules/certificate/object-erasure.service.ts ← reached from a request
```

### The four

| Route                                  | Reaches                                                                                                     | Worst case while holding a pooled connection                    |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `GET /courses/:slug/media-check`       | `MediaCheckService.check` → sequential loop, `AbortSignal.timeout(8_000)` each                              | **8 s × N distinct URLs.** A five-module course probes fifteen. |
| `GET /courses/:slug/certificate` (pdf) | `CertificateService.download` → `archiveOnce` → `CertificateArchive.store` — a real `PUT` of the PDF bytes  | 15 s                                                            |
| `POST /courses/:slug/completion`       | `issueForEnrolment` → same `archiveOnce` → same `PUT`                                                       | 15 s                                                            |
| `DELETE /admin/learners/:enrolmentId`  | `ModerationService.eraseSubject` → `ObjectErasureService.drain()` — potentially **many** sequential deletes | 15 s × objects                                                  |

`media-check` is the worst in aggregate and the least sensitive. The other three
touch **certificates** and **erasure**, which is the `CLAUDE.md` §2 human-review
set — so they are written up rather than refactored at the end of a long
session. A rushed change to the path that issues a physician's
Teilnahmebescheinigung is not an improvement on a bounded stall.

### What each is worth

None of these can hang: P144 bounded every call. All four can occupy request
connections for their bound, and `media-check` can occupy one for minutes on a
course with many distinct hosts. `ds_pg_pool_waiting` (P144-02) is what will
show it.

### The shape of the fix

The same as P145: `@NoAmbientTransaction()` plus a `TenantRunner`, with the
network call between segments rather than inside one. `media-check` is the
cleanest — it reads the URL list, then probes — and should go first, because it
is the largest exposure and touches nothing under §2.

design, and then applied it to exactly the routes I happened to be looking at.
