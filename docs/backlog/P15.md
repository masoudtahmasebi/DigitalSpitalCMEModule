# P15 · How a course behaves: length, resuming, seeking, points

Six behaviours the client specified after the layout was settled. They are not
cosmetic: four of the six decide what a learner is shown of material that awards
a CME point, and one of them decides whether the accreditation's "must be seen"
holds at all.

**Review gate: human — assessment.** P15-01 changes what forward seeking is
permitted and P15-03 changes when the Fortbildungsnummer is required. Both are
conditions of a Punktemeldung.

## Why this exists

The client's message, in their own words:

> the time of the course will be auto calculated from the videos which are
> uploaded. there can be courses which do not have any points, because there can
> be educational courses in the future which have no points. `Zur Fortbildung`
> button is for starting the course from scratch and it will bring you directly
> to the course start page. `Fortbildung fortsetzen` helps you to continue where
> you left of the course if you have started it, you will go back to the video
> which you were watching, or if they have completed a video, they will go to the
> next step, so if a user has finished chapter one and they leave, when they come
> back they would start from chapter 2. can we make it possible to go back to the
> start of the minute which they were watching? for example if a user leaves on
> the time of the video two on 14:35 and they leave again, if they start again
> after they have left, the video starts from the minute 14, on 14:00. they
> should not be able to seek through the video and go forward, they should watch
> the whole video. the inhalte section should be generated automatically from the
> inhalt the course created of admin panel.

Two of the six were already true and are recorded here so the next reader does
not implement them twice.

## P15-01 · Resuming, and the ceiling on seeking — **done**

- **Estimate:** 5 h · **Depends on:** P3-03

**Scope**

- `@ds/domain/resume`: `resumePosition`, `seekCeiling`, `clampSeek`,
  `clampSeekToLimit`, `playerSeekLimit`.
- `resumeAtSec` and `seekCeilingSec` on `LessonContent`; `seekCeilingSec` on
  `ProgressResult`, so the player's limit advances with every flush.
- `VideoPlayer`: one clamp on every seek path, a snap-back on the element's own
  `seeking` event, a hatched locked region on the scrub bar and a sentence
  saying why.

**Acceptance criteria**

- [x] A learner who leaves at 14:35 resumes at **14:00** — the containing
      minute, not "sixty seconds back", which lands somewhere arbitrary
- [x] Resuming never lands past the end of the video, nor past the seek ceiling
- [x] Forward seeking stops at the end of what was actually watched; backwards
      is unrestricted, because a union counts each second once
- [x] Every seek path is clamped — scrub bar, arrow keys, J/L, digit shortcuts,
      Home/End — and the element's `seeking` event catches Picture-in-Picture,
      media keys and iOS fullscreen controls, which the component does not own
- [x] A _playing_ video is never dragged backwards between flushes: the limit is
      the further of the server's ceiling and this session's own playback, and
      only playback raises it — a seek cannot raise its own ceiling
- [x] The restriction is visible: `aria-valuemax` follows the limit rather than
      the duration, and the locked remainder is hatched, not merely a fifth grey
      (WCAG 1.4.1)
- [x] A missing `seekCeilingSec` lifts the restriction rather than locking the
      player — the gate is the union, and locking would cost every learner for
      no compliance gain
- [x] The ceiling is derived from the validated segments, never from the
      client-reported `lastPositionSec`, and `resumeAtSec` is capped at it

**Notes.** The clamp is a courtesy and the header comments say so. A skipped
passage leaves a hole the union never fills, so nothing here is load-bearing for
the CME point — what it buys is a learner who can see why their percentage is
stuck, instead of one who drags to the end and is silently refused.

## P15-02 · A video's length, read from the video — **done**

- **Estimate:** 2 h · **Depends on:** P9-02

**Scope**

- `apps/admin/src/media-duration.ts`: `probeableSourceUrl` (pure, tested) and
  `probeDurationSec` (a `<video preload="metadata">`).
- An "Aus Video ermitteln" button beside the length field.

**Acceptance criteria**

- [x] The course's total length is the sum of its videos' lengths and is not
      separately authored — already true (`catalog.repository.ts`), now stated
      in the field's own hint so nobody adds a second field for it
- [x] A per-video length can be read out of the file instead of typed
- [x] Offered, not automatic: an author editing an existing item may have a
      deliberate figure there, and overwriting a decision with a measurement
      without saying so is worse than a button
- [x] Rounded, not truncated — truncating shortens every video by up to a
      second, which on a 100 % gate is a second nobody can watch
- [x] `s3://` keys and CORS-less origins fail gracefully with an explanation,
      because both are ordinary and neither is the author's mistake
- [x] The button is absent entirely when no source is fetchable

**Deliberately not done.** Server-side probing. Reading a container's duration
in the API means ffprobe in the image, which is the first step of a media
pipeline — and media transcoding is out of scope (CLAUDE.md §3). The browser has
a decoder already.

## P15-03 · Courses that award no points — **done**

- **Estimate:** 2 h · **Depends on:** P6-03

**Scope**

- `awardsCmePoints` on the completion input in `@ds/domain/completion`.
- `cmePoints` threaded from `enrolments` through both repositories to
  `summariseEnrolment`, which is the one place completion is decided.

**Acceptance criteria**

- [x] A course with no CME points does not require a Fortbildungsnummer
- [x] It is the _enrolment's_ points, not the course's: the enrolment snapshots
      what the course was worth when it was taken, so re-pricing a course cannot
      rewrite a completed record
- [x] The refusal message for such a course never mentions the EFN, which would
      send a learner looking for a field the course does not have
- [x] An accredited course is unchanged — asserted by the same suites

**Notes.** The reason is not convenience. With no points there is no
Punktemeldung, so there is nothing an EFN would identify, and collecting a
physician's national identifier for a purpose that does not exist is exactly
what ADR-0004 exists to prevent. `docs/gdpr.md` §2 already scopes the EFN to the
Punktemeldung; this makes the code agree with it.

## P15-04 · Two catalogue buttons, two destinations — **done**

- **Estimate:** 2 h · **Depends on:** P5-02

**Scope**

- `OpenIntent` through `CourseList` → `App` → the `ds-lms:course-open` detail →
  the portal's route → the `open-at` attribute.

**Acceptance criteria**

- [x] **Zur Fortbildung** opens the course's start page
- [x] **Fortbildung fortsetzen** opens the player at the resume point — the
      video they were watching, or the next content if they finished it
- [x] Which content that is comes from the server's `resumeContentId`; the
      client does not work out what comes after a finished chapter
- [x] Applied once. Returning to the outline from the player is the learner's
      decision, and re-applying the intent would trap them in the video
- [x] A routing host is told which button was pressed and can honour it with
      `open-at="resume"`; a host that ignores it gets the old behaviour
- [x] The intent is not in the URL — a bookmarked "resume" link would drop
      whoever opened it into the middle of a video, possibly someone who had
      never started the course

## P15-05 · The Inhalte section — **already true**

The Inhalte list on the course detail is built from `course.modules` — the
structure authored in the admin console — with each module's length summed from
its own contents. Nothing is authored twice and nothing is hard-coded. Recorded
here so the acceptance criterion is discharged rather than silently assumed.

See `OverviewTab.tsx`, the `Section title={de.overviewTab.contents}` block.
