# P61 — What the QA pass through the widget found

Raised 12.08 by the QA agent's Section 9, driven with Playwright against the
**built** `ds-lms.js` on a deliberately hostile host page — pink buttons, serif
body font, `box-sizing: content-box` — which is the closest thing available to
the WordPress theme it will live inside.

Twelve cases. One defect, and it is the visible half of a ticket that already
said it was missing.

---

## P61-01 · The Punktemeldung form did not ask for the Anschrift · 0.5 h

**Status: done.**

P60-03 gave the platform somewhere to put a postal address, said in its own
ticket that _"no screen offers the field yet"_, and named Section 9 as where it
would be added. Section 9 found it, which is the system working: the API
accepted `attestedAddress`, the certificate printed whatever was stored, and
nothing could ever store anything. CLAUDE.md §9.3 — a rule written is not a
rule enforced — one layer up from the domain, in a form.

The field is now on the form, between the name and the EFN, with no asterisk
and a line saying what happens if it is left empty:

> Optional. Wird auf der Teilnahmebescheinigung ausgewiesen; ohne Angabe bleibt
> die Zeile leer.

Said at the point somebody looks for it (§9.4). A postal address on a form that
otherwise wants only a name and an EFN raises "must I?", and the answer belongs
next to the box rather than in a support ticket.

**Empty means omitted, not `""`.** The API reads an absent field as "not
supplied in this request" and leaves whatever is stored; an empty string is a
value, and would blank an address a learner gave on an earlier attempt.

Verified end to end in the browser: typed into the form → stored on the
enrolment → printed on the downloaded PDF as `Anschrift: Musterstraße 1, 58638
Iserlohn`, beside `EFN: 800276111222333` (P60-02). Verified red: deleting the
one line that puts it in the request turns the "sends what was typed" case red
and leaves the other three green.

## What Section 9 confirmed as already correct

Every case below ran against the built bundle. The widget's shadow root is
**closed** — a host page cannot reach inside it — so the harness forces it open
before any page script runs; nothing about the bundle changes, only what the
test can see.

- **9.1 — mounts clean.** `<ds-lms>` defined, shadow root attached, **zero**
  page errors and zero console errors. No JWT in the rendered HTML, in the
  shadow DOM, or in any console line. Two API calls on mount: `GET /branding`,
  `GET /courses`.
- **9.2 — the catalogue.** Cards carry points, module count, duration, title,
  description and "Zur Fortbildung". Selecting a Thema filtered two courses to
  one.
- **9.3 — all four tabs.** _Übersicht_ (description, six Lernziele, Zielgruppe,
  module list with durations), _Experten/Referenten_ (two cards with name, role,
  institution, bio), _Zertifizierung_ (points, Akkreditierung with the validity
  window, three Voraussetzungen, the Punktemeldung explanation, Ihr Zertifikat),
  _Mediathek_ (grouped by module, per-module filter, each material with a size
  and _"Wird nach Abschluss der Module freigeschaltet"_ on the locked ones).
- **9.4 — the progress ring.** "Ihr Fortschritt", an SVG ring reading _0 von 5_,
  the sentence beneath it, the percentage against the requirement, and the
  orange CTA. It read _5 von 5_ with a "Fortbildung abgeschlossen" badge after
  the journey, without a reload.
- **9.5 — the player.** Video plays (`currentTime` advanced under observation),
  the module rail shows every module with per-module counts and the current
  chapter highlighted, later modules are locked, _"Ihr Fortschritt wird
  automatisch gespeichert"_ is on screen, the percentage moved 0 % → 30 % → 100 %
  as segments were reported, and a keyboard-shortcut legend is visible.
- **9.6 — forward seeking is refused.** Watched to 2.0 s, then clicked the
  player's own scrub bar at 95 % (≈7.2 s): the playhead landed at 6.65 s — the
  ceiling is `maxWatchedPosition + 5 s` by design — and the **server credited
  28 %**, not 95 %. Two independent defences, and the one that matters is the
  server's.
- **9.7 — the quiz.** One question at a time, radio buttons for single choice,
  "Frage n von 11", advance on Weiter, "Antworten absenden" on the last. Fail →
  _"⟳ Abschlussprüfung wiederholen"_; pass → _"Abschlussprüfung bestanden! 11/11
  · 100 % · 8 von 11 richtige Antworten zum Bestehen erforderlich"_ and
  _"CME-Punkte geltend machen →"_. **The answer key is nowhere**: not in the
  rendered DOM, not in the React props of any node, not in the network payload.
  And the screen says so: _"Die richtigen Antworten werden aus Gründen der
  Zertifizierung nicht angezeigt."_
- **9.8 — the Evaluationsbogen.** Two required scale questions and a free-text
  box, with _"Pflichtfragen sind mit * gekennzeichnet"_, refusing submission
  until both are answered, then advancing to the Punktemeldung.
- **9.9 — the EFN.** Ten digits was refused with _"Die EFN muss aus genau 15
  Ziffern bestehen."_ and the form stayed put; fifteen digits was accepted. The
  step is skipped when one is already stored — the screen then shows the number
  back with a correction affordance (P54-02).
- **9.10 — completion.** "Herzlichen Glückwunsch! Sie haben die Fortbildung
  abgeschlossen" heads the Punktemeldung step; after submitting, the learner
  lands on _Zertifizierung_ with the participation record filled in — name, VNR,
  date, time, Ort, Veranstalter, the creditability sentence — and
  "Teilnahmebescheinigung herunterladen". A `certificates` row existed
  immediately (P59-01, now confirmed through the UI rather than the API).
- **9.11 — responsive.** 1440 / 1024 / 768 / 375 px: **no horizontal scroll at
  any width**, and no element extends past the viewport at 375 px.
- **9.12 — keyboard.** Twenty-two tab stops on the course detail and twenty-two
  in the player, every one of them with a visible focus ring. The three stops
  without one were on the **host page**, which is correct: tabbing out of the
  widget leaves the widget.

### Two differences from the section's wording, neither a defect

- **There is no `GET /api/me`.** The catalogue does not read a profile, because
  it does not need one — the widget is mounted inside a site that already knows
  who is signed in, and an extra round trip per mount would buy nothing. The
  endpoint that exists is `GET /auth/participant/me` (P54-01) and the widget
  calls it where it matters.
- **The filters are selects, not chips.** "Thema auswählen" / "Altersgruppe
  auswählen" dropdowns, which is what the Zeplin layout draws. They filter, and
  the count beside each option comes from the same query the list does.

### The two things the environment could not show, and why

Both are §9.9 in the other direction — the installation is not the repository:

- **The seeded course points at `media.example.org`**, which does not exist. QA
  served a real WebM locally to exercise playback. Nothing about the widget is
  wrong; the seed's media URLs are placeholders awaiting MEDICE's files.
- **A media host must answer `Range`.** Python's `http.server` does not, and
  without `206` the browser cannot seek at all — which looks exactly like the
  player refusing a seek and cost an hour before it was noticed. Worth writing
  down before somebody puts the videos behind a plain static server.
